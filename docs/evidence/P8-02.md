## Implementation decisions where the approved spec is silent

These are for the owner to confirm. The spec is not edited.

1. **Booleans in arithmetic** (`TRUE + 1`) give `#VALUE!`. This follows spec §6 (no implicit conversion). The spec does not state it directly.
2. **Boolean ordering**: `FALSE < TRUE` for `<`, `<=`, `>`, `>=`. The spec says mixed-type ordering is `#VALUE!`, and booleans are one type, so ordering is allowed.
3. **Date vs datetime comparison** uses instants. A date means local midnight. This matches §6.
4. **Datetime text** (`&`, CONCATENATE) uses `YYYY-MM-DD HH:mm` with no seconds, as §6 says.
5. **Text comparison** orders by Unicode code point, as §6 says. Case-insensitive `SEARCH`/`FIND` lowercases one code point at a time. Characters whose lowercase form has a different code-point count are kept as-is.
6. **Internal exceptions**: function code uses an internal `FormulaFault` to unwind one call. `evaluate` converts it to an error value. Any unexpected exception is counted in `stats.internalErrors` and returns `#VALUE!`. The count must stay 0 and is asserted in the tests.

## Deviations

- The golden suite was intended to run under `TZ=Asia/Dhaka`. Setting `process.env.TZ` inside a vitest worker does not change the zone. The suite is therefore TZ-independent (inputs and outputs are both local) and was run under both UTC and `TZ=Asia/Dhaka`. Both pass.
- FX-M single-edit timing is far below target because one edit touches one row. The full-table recalculation is recorded as well, so the bound is not only the single-row case.
