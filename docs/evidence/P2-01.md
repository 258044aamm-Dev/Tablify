## Edge cases documented

- `field:a,b` on text → `containsAny` (substring OR); on `single_select` → `isAnyOf` (exact ID OR); on `multi_select` → `containsAny` (array OR); numeric/date → `equals OR`. Quoted `"a,b"` is one value.
- `field:empty` (keyword, unquoted, CI) vs `field:` (empty value `[""]`) vs `field:"empty"` (quoted value) vs `field:""` (quoted empty) — parser distinguishes; evaluator treats first three as empty predicate.
- Operators `~ ! > <` consume exactly one value; comma after them is error (`"Comma not allowed after '>' operator"`).
- Colon in unquoted value → error (`"Unexpected ':' in value — quote the value if it contains ':'"`); quoted value may contain colon.
- Whitespace around `:` and `,` is ignored/trimmed; inside quotes preserved.
- Quote escaping is doubled `""` (CSV-style), not backslash.

## Ambiguous cases decision (strict_each, owner-approved 2026-10-09)

Documented in `docs/query-grammar.md §4` and `§9` table. Both text and select use OR, but inner match differs: text does substring, selects do exact option ID. This avoids silent mismatch where `title:ship,boat` would otherwise be exact-match-only (too narrow) vs `status:Done,Todo` must be exact.
