## Objective

The filter bar provides global search, a non-empty field value filter, a query builder, an invalid query message, a multi-field sort menu, and a toolbar that can hold an arbitrary number of filter and sort entries.

## Deliverables

- `src/views/grid/filterBar.ts` — `searchRows(rows, getCells, query)` (case-insensitive, uses `visibleText` for select so label, not raw value), `filterByQueryAST(rows, fields, ast, getValue)`, `parseQueryInput(input)` (wraps `parseQuery`), `addTermToQuery(current, field, op, value)`, `sortAdd/sortRemove/sortMove`, `debounceApply(input, onApply, delay)` (clears timer on cancel, does not apply instantly)
- `tests/views/grid/filterBar.test.ts` — 7 tests: global search matches string/number, select not matched via raw value but via visibleText, non-empty field filter `Text:hello`, builder adds condition, invalid query shows message with `position/line/column`, sort menu add/remove/move priority, toolbar debounce, perf 5k rows <200ms
- No new UI chrome — filterBar is pure logic used by `GridView` to drive the toolbar; avoids hard-coded colors.

## Correction — the visual toolbar (SAD-69)

> **This section supersedes the "NOT RUN" note above.** It was written when `src/views/grid/toolbar.ts`
> did not exist: P3-08 delivered the filter logic and recorded that the visual toolbar still needed
> a real vault. That turned out to be the wrong reason. The logic was never rendered anywhere, and
> no test could have caught it, because no test could import `TableView` — there was no `obsidian`
> mock in the repo. The toolbar was not "unverified on a device"; it was **absent**, and nothing
> was positioned to notice.

**Commits:** `f1caa8f`, `0171ad8`, `ec72203`, `8b935b8`, `51cc9f3`, `38f9f2c` (Linear SAD-69).

### What was delivered

`src/views/grid/toolbar.ts` — the file this step specified as its output and that was never in the
repo. Plain DOM, no Obsidian imports, so it is testable in jsdom like `GridView`. `TableView`
mounts it in `onOpen()` and refreshes it through `update()` on every render.

Controls follow `Prototype/Anthropic Table Workspace.html`: a search capsule, **Add Row**,
**Add Field**, **Options**, **Undo/Redo**, a query field with inline errors, and a row-count
badge (`40 rows` / `12 of 40 rows`).

- **Options** panel: row height (small / medium / large), freeze columns, hidden fields with a
  **Show** button each, and **Clear filters**.
- Search and query are debounced at **200 ms** (the toolbar uses its own `DEBOUNCE_MS`, not
  `debounceApply`'s 250 ms default) and are persisted in the file's `views` section.
- Search and query are **not undoable**. They route through `TableSession.patchView()`, added for
  this purpose, so typing does not push an undo entry per debounce tick.

### Why it could not be caught before

`tests/__mocks__/obsidian.ts` now exists, aliased through `vitest.config.ts`. It covers every
Obsidian API `src/` imports plus the DOM helpers Obsidian adds to `HTMLElement`. This is the
unblocking change: without it `TableView` and `tableMenu` were unimportable in tests, which is
precisely how a specified UI could ship unbuilt.

A throwaway test written against the pre-fix tree confirmed the bug in code: the view built
exactly `['Add row', 'Undo', 'Redo']` and contained no `<input>` at all.

### Two real bugs the new tests found

1. `GridView` recycled pooled row elements and set `style.height` only when an element was
   created, so the row-height control did nothing to rows already on screen.
2. The header is the viewport's **sibling**, not its child, so horizontal scrolling moved the body
   and left the header behind. Pre-existing, but invisible while every column was `flex: 1`. The
   header is now its own scroll container and mirrors the viewport's `scrollLeft`.
