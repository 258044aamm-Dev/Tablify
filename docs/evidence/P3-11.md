## Objective

Every text/background pair on Core, 720 XP-12 Pro, and FX-M in light and dark themes meets WCAG 2.1 AA (4.5:1 body). Accents that fail AA are documented as non-text.

## Deliverables

- `src/ui/theme/contrast.ts` — `hexToRgb`, `srgbToLinear`, `luminance(hex)`, `contrastRatio(a,b)`, `meetsAA(ratio, large?)` (WCAG formula `(L1+0.05)/(L2+0.05)`)
- `src/ui/theme/tokens.ts` — already P3-09 (palette: dark #141413, light #faf9f5, midGray #b0aea5, lightGray #e8e6dc, accentOrange #d97757, accentBlue #6a9bcc, accentGreen #788c5d; lightTheme bg #faf9f5/text #141413, darkTheme bg #141413/text #faf9f5)
- `scripts/check-contrast.mjs` — Node runner that prints 12 pairs with ratio, AA/large pass, and intended use; exits 0 only if body text pairs pass AA
- `tests/ui/contrast.test.ts` — 6 tests: light text/bg AA, dark text/bg AA, orange on light fails AA but passes on dark, blue on light fails, green on light fails AA but passes large (3:1), muted/border on light fails AA & <3:1

## Automated contrast results

Run `node scripts/check-contrast.mjs`:

```
light: text on bg: #141413 on #faf9f5 → 17.50:1 — AA PASS / Large PASS — body text — must pass AA 4.5
dark: text on bg: #faf9f5 on #141413 → 17.50:1 — AA PASS / Large PASS — body text — must pass AA 4.5
light: muted on bg: #b0aea5 on #faf9f5 → 2.11:1 — AA FAIL / Large FAIL — secondary/border — not body text
dark: muted on bg: #b0aea5 on #141413 → 8.29:1 — AA PASS / Large PASS — secondary/border — not body text
orange on light: #d97757 on #faf9f5 → 2.96:1 — AA FAIL / Large FAIL — accent — selection/focus, not body text if <4.5
orange on dark: #d97757 on #141413 → 5.90:1 — AA PASS / Large PASS — accent on dark
blue on light: #6a9bcc on #faf9f5 → 2.78:1 — AA FAIL / Large FAIL — secondary accent — links if <4.5 use for non-text only
blue on dark: #6a9bcc on #141413 → 6.30:1 — AA PASS / Large PASS — secondary accent on dark
green on light: #788c5d on #faf9f5 → 3.49:1 — AA FAIL / Large PASS — success accent — non-text if <4.5
green on dark: #788c5d on #141413 → 5.01:1 — AA PASS / Large PASS — success accent on dark
lightGray on dark (stripe): #e8e6dc on #141413 → 14.73:1 — AA PASS / Large PASS — stripe bg — not text bg pair
midGray border on light: #b0aea5 on #faf9f5 → 2.11:1 — AA FAIL / Large FAIL — border — UI component 3:1
```

Interpretation per `spec/branding.md` §5 rule:

- Body text pairs **PASS AA 4.5:1** in both themes (17.5:1) — required.
- Accents orange (#d97757), blue (#6a9bcc), green (#788c5d) **FAIL AA on light** (2.96, 2.78, 3.49) — so they are **not used for body text on light**; they are used for selection, focus ring, and non-text UI (where 3:1 is the UI component threshold). On dark they PASS AA, so they are safe as text on dark.
- Muted (`#b0aea5` on `#faf9f5` 2.11) and border (same 2.11) **FAIL AA and <3:1 on light** — documented as secondary/border, not body text; on dark they pass (8.29:1) so muted text on dark is fine.
- This matches the spec line: “Check the orange and green accents as text on light backgrounds before use; use them for non-text elements if they fail.” — done; they are non-text on light.

## Coverage notes

- Contrast helper uses the standard sRGB linearization (`≤0.04045 ? /12.92 : ((+0.055)/1.055)^2.4`) and `0.2126/0.7152/0.0722` coefficients — matches WCAG.
- Every semantic token resolves via `palette` only — no hex outside `tokens.ts` (enforced by `tests/ui/tokens.test.ts`).
- No CSS changes — `applyTheme` still sets `tablify--light/dark` class plus inline `var(--tablify-*)` so the grid on Core and FX-M uses the same verified tokens.
