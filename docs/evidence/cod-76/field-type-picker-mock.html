The field type picker

Today the Field type row is a native <select>. The list that opens is drawn by the operating system: it ignores the theme, cannot carry an icon or a description, and on a phone it is the OS's own full-screen drawer. This board replaces it with a picker the plugin draws — searchable, grouped, keyboard-first, themed — without moving a single type out of the model.

03 Modify mode — the types that would drop values, explained

Changing a Number column whose cells hold abc cannot offer Text → Number… silently. Today those types simply vanish from the list, which reads as a bug. They now stay in place, greyed, and say why — the reason is the one planTypeChange() already returns; no new rule is invented here.

04 Phone — 390 px, the same card, clamped

No bottom sheet, no OS drawer. The panel is the width of the trigger, capped to the viewport − 32 px, and its list scrolls inside a 60 % of viewport cap so the Save button never leaves the screen. On a coarse pointer the search box is not focused on open — the keyboard would eat the list; the current type is scrolled into view instead.

06 Behaviour, stated as rules

  • Open — click, or Enter / Space / ↑ / ↓ on the closed trigger. The list scrolls the current type into view.
  • Search — filters on the type name and on hidden keywords (money → Currency, stars → Rating, clock → Date and time). No match → an empty state with Clear search.
  • Pick — click, or Enter on the highlighted row: the trigger updates, the panel closes, focus returns to the trigger, and the window's dependent rows (Options / Min–Max / Regex / Formula / Linked table) show or hide exactly as they do today.
  • Dismiss — Esc, a press outside, or Tab. The type does not change.
  • Blocked rows stay visible, aria-disabled="true", with the reason in place of the description; clicking does nothing.
  • Nothing else moves — the committed type, the extras, the notices, the patch built on Save and onConfirm's arguments are untouched.

07 Keyboard & assistive tech

↓ / ↑
next / previous row, skipping blocked ones, wrapping
Home / End
first / last selectable row
Enter
pick the highlighted row
Esc
close the panel, keep the window open, focus back on the trigger
Tab
close and move on — the popup never traps focus
A–Z
typing when the trigger is focused opens the panel with that letter in the search

The current row's glyph and check use textToday (the AA terracotta), not the raw accent: the accent measures 3.28:1 on the white panel (2.99:1 on its own tint), and a 13 px glyph owes 3:1. Measured: 4.78 / 5.09 on the panel, 4.36 / 4.48 on the tinted row.

A blocked row is not dimmed as a whole: fading it to 55 % would take its reason to ≈2.5:1 on white, and the reason is the one thing you need to read. Only the decorative icon fades.

The trigger is a button with aria-haspopup="listbox", aria-expanded, and a label of “Field type: Date”; the panel is a role="listbox" of role="option"s with aria-selected on the current one and aria-activedescendant following the keyboard cursor while focus stays in the search box. Group headings are role="group" + aria-labelledby, so a screen reader announces “Basic, group” before the row name.
