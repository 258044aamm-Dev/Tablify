## Change

### One "Search or query" box (prototype `#toolbarRow`, `Prototype/index.html` 146-178)

The toolbar had two inputs: **Search** (free text) and **Query** (`field:value`). The prototype has one mono pill. They are merged, with no change to the file format or the filter engine:

- **New `src/query/combined.ts`:**
  - `splitSearchQuery(text)` lexes the box with the strict query grammar's own tokenizer rules. Every `field:value` term goes to the query, and every other word goes to the search.
  - `joinSearchQuery(search, query)` rebuilds the box from the two saved halves (search first).
  - `toInputPosition` maps a parser error position back to a column in the box.
- **Persistence is unchanged.** The two halves are saved as `view.search` and `view.query`, as before. Files written before this step open with their search and query joined in the box. Undo remains limited to edits (§9).
- **Errors** appear under the box with the position counted from the start of the box, and the box gets `tablify__search-input--invalid`. Free words never error. An invalid query fails open: only the search words apply (`filterRows`, unchanged).
- Debounce is 200 ms, as before. `setFilterText()` cancels a pending debounce, so Apply from the builder is not overwritten by a late keystroke.

### Filter builder (prototype `#filterModal` + `script.js` 1697-1782)

`src/views/grid/filterBuilder.ts` (model + DOM) and `FilterBuilderModal.ts` (Obsidian `Modal`, the plugin's own close button):
- rows read *Where / and · field · operator · value · trash*;
- **Add condition**;
- the live **Equivalent query string**;
- **Clear all · Cancel · Apply filter**.

Each row is exactly one query term, so the builder and the box cannot disagree. Apply writes the box through `toolbar.setFilterText()`, so it is saved and filtered in the same tick as typing.

## Decisions and deviations from the prototype

1. **Operator lists = prototype ∩ what the plugin's evaluator accepts.** The prototype offers three operators the plugin's query engine rejects. Offering them would produce an error on Apply, so they are dropped:
   - text "is not" (`evaluate.ts` allows `!` only on single select);
   - multi-select "does not contain";
   - number "≠".

   Formula and link fields are not listed, because the evaluator returns *Unsupported field type* for them. A test compiles every offered operator for every field type through the real evaluator. If a typed query uses an operator the list does not offer (e.g. `Name:!x`), the row keeps it as an extra option, rather than silently rewriting the user's query.
2. **Exact values (the prototype's builder is lossy).**
   - **The prototype's problem:** it joins list values with `, ` and splits on every comma. So `Tags:"a,b"` turns into two values, and quoted leading or trailing spaces are lost.
   - **The fix:** the builder uses the grammar's own quoting inside the value box:
     - commas outside quotes separate values;
     - `"…"` keeps commas, quotes (written `""`) and surrounding spaces;
     - unquoted items are trimmed.

     `encodeListValue`/`decodeListValue` and `encodeSingleValue`/`decodeSingleValue` implement this.
   - **The check:** a seeded property test (400 random ASTs over the FX-M differential fixture fields, values with spaces, commas, quotes and unicode). For each one it runs box → builder → Apply, then checks that the parsed terms are identical and that `evaluateQuery` selects identical row ids on the 1,000 fixture rows.
3. **Unknown fields are kept, not remapped.** The prototype silently maps a term on an unknown field to the first field. The plugin keeps such terms verbatim, lists them in a note, and re-appends them on Apply. A query with a parse error is reported in the note, and Apply replaces only the query part. Search words are always kept.
4. **Mobile toolbar scrolls.** At 390px the prototype's button group overflows the card, and Add Row / Add Field squeeze to two-line 54px pills (visible in the harness crops). The plugin instead gives the box its own row (<640px) and lets the buttons scroll sideways in one line: `overflow-x:auto`, hidden scrollbar, and a 4px padding / −4px margin so focus rings are not clipped. This is the one intentional geometry difference: toolbar-row height 86 vs 102px on mobile.
5. **Placeholder.** The prototype's example uses its demo fields (`Task:~grid "Estimate (h)":>5 Tags:UI,Perf`). The plugin keeps a generic example (`Search or query — e.g. Status:Done Amount:>10`). The preview heading drops the "(spec §2.6)" annotation.
6. **Apply filter ink and focus rings.**
   - The Apply button uses the theme's on-accent ink, like every accent pill since SAD-71. White on the light terracotta is 3.2:1 and fails WCAG AA for 12px text.
   - Focused inputs keep the 2px focus outline in addition to the prototype's accent border and ring (WCAG 1.4.11).
