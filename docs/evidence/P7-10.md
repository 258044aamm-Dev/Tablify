# Evidence: P7-10 sync UI (link, pull, push, status, conflicts, field creation)

Status: **built and tested in jsdom. Obsidian runtime and visual checks NOT RUN.**

## What was built

- `src/views/sync/SyncModal.ts`: the modal. Sections, from top to bottom:
  - Token status. It says whether a token is stored and never shows the value.
  - Scopes text, which matches the prototype's line.
  - Link form: base and table pickers, a checkbox to replace local columns, and a Link button.
  - Unlink, when linked.
  - Pull and Push buttons. They are disabled when unlinked, when no token is stored, or while an action is running.
  - Progress line, status line (with a clear "Nothing in the table changed" on network failures), and last-sync line.
  - Conflict list with keep local, keep remote, and keep both. Remote-deleted conflicts offer keep local and remove row only.
  - Field check. It lists fields to create (and skipped fields with reasons). Cancel comes first and is focused. Create is a separate button.
- `src/views/sync/syncController.ts`: link and unlink.
  - Default link matches local columns to Airtable fields by name and type. Unmatched columns stay local.
  - Replace columns swaps the local columns for the Airtable schema and clears the old link first.
  - Unlink clears sync blocks and field links. Local values are kept.
- `src/views/tableView.ts`: two public hooks, `syncSession()` and `afterSyncChange()`.
- `src/main.ts`: command **Airtable sync for this table** (`tablify-airtable-sync`). It is a command, not a toolbar button, so Task A's toolbar parity is unaffected.
- `styles.css`: `.tablify-sync*` rules. They use existing tokens only (the theme test forbids color literals).
- `README.md`: sync setup section with the scope list (P7-09 item 4).

## Differences from the prototype, on purpose

- No token input. The prototype shows a demo token. Production shows only whether a token is stored (P7-03, settings only).
- Not marked SIMULATED. The actions run the real engine.
- Field options and the Keep both copy are described in `docs/sync-rules.md`.

## Tests

- `tests/views/syncModal.test.ts`: 9 pass.
  - Token status shows no value, and actions are disabled when unlinked.
  - No token means no Airtable calls.
  - Link, then pull, then status line.
  - A conflict shows its choices, and Keep both adds one row.
  - Field check lists fields, and nothing is created until the button is clicked.
  - A network failure shows the message and changes no rows.
  - Controller: name matching, replace columns, unlink keeps values.
- Full loop (link, pull, edit, push, pull) is covered by the engine tests in `tests/sync/engine.test.ts`. The fake server is used, not a live base.
