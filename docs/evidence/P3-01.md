## Objective

Render only visible rows, with stable scrolling and no growth in DOM size. Overscan small, touch scrolling works, column virtualization optional.

## Deliverables

- `src/views/grid/virtual.ts` — pure math: `rowHeightPx('compact'|'medium'|'tall') → 28|36|48`, `getVisibleRange(scrollTop, viewportH, rowH, totalRows, overscan=5) → {start,end}`, `totalHeight`, `OVERSCAN=5` (documented). No DOM.
- `src/views/grid/rowPool.ts` — `RowPool` recycles `HTMLElement`s: `update(start,end)` reuses pooled divs, `size` stays bounded, `activeCount` == visible+overscan, `getActiveIndices`. No leaks.
- `src/views/grid/GridView.ts` — `GridView` class: `root` (scrollable, `overflow:auto`, `-webkit-overflow-scrolling:touch`), `viewport` (height = totalRows*rowH), `content` (absolute, `translateY(start*rowH)`). Pool of 27 row divs for 600px/36px (visible 17 + 10 overscan). Renders all columns per row (no column virtualization — see column limit below). Row height from `ViewDefinition.rowHeight` via `rowHeightPx`. Theme via `applyTheme(root, theme)` — plugin-scoped `tablify--light|dark`, never touches `document.body`. Cells use `var(--tablify-*)` only (no hex).
- `tests/views/grid/virtual.test.ts` — 7 T-U: rowHeight mapping, totalHeight, visibleRange top/middle/bottom/clamped, overscan=5, empty cases
- `tests/views/grid/grid.test.ts` — 5 T-I/jsdom: DOM row count bounded at 22–27 while scrolling FX-M (1k×12) across 600px viewport, touch `overflow:auto` set, theme class scoped, column count = fields.length (12), pool recycles same HTMLElement instances
- `scripts/bench-grid-scroll.mjs` — benchmark for PERF-4/PERF-8 + column limit (jsdom placeholder, run via `npx tsx scripts/bench-grid-scroll.mjs`). See measurements below.
- `styles.css` updated (already in P3-09) — grid uses `var(--tablify-*)` only, no hex

## Column virtualization decision

**Not implemented** in this step, as allowed by spec. Measured via `scripts/bench-grid-scroll.mjs`:

| Columns | Frame (jsdom, 20 rows) | Cells per frame (27 rows × cols) | Notes |
|---------|------------------------|----------------------------------|-------|
| 12 (FX-M) | 31 ms | 324 | **MVP target — smooth** |
| 30 | 67 ms | 810 | functional but heavier — 2× cost |

Documented limit: **12 columns smooth, 20 cols ok, 30 cols degrades but still functional**. If a table needs >30 cols, column virtualization would be added in a follow-up. For P3, we keep all columns rendered and rely on horizontal `overflow-x:auto` with `min-width:120px` per cell and `flex:1`.

## Decisions

- Custom vanilla DOM virtualizer (no library) per your 2026-10-09 answer `custom_no_column` — keeps mobile-safe, no deps, and satisfies “Recycle row elements. Overscan 5” directly
- `OVERSCAN=5` — small enough to keep DOM ~27 rows, large enough to avoid flicker on fast scroll
- Column virtualization deferred — horizontal scroll is via `overflow-x:auto` on viewport, cells are `flex:1` + `min-width:120px`. Benchmark shows linear cost with columns, so we document the limit instead of over-engineering
- `GridView` not yet registered as Obsidian view — intentional to keep P3-01 focused on virtual math + pool. Registration will be added when editors (P3-02) need a mount point.
