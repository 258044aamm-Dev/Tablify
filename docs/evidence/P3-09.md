## Objective

One token source for all table UI colors, spacing and type. Light and dark Anthropic-inspired themes that apply via a plugin-scoped class on the table root, independent of the Obsidian theme.

## Deliverables

- `src/ui/theme/tokens.ts` — single source, palette from `spec/branding.md` §5 exact values (unverified, G-B1 open):
  - `dark: #141413`, `light: #faf9f5`, `midGray: #b0aea5`, `lightGray: #e8e6dc`, `accentOrange: #d97757`, `accentBlue: #6a9bcc`, `accentGreen: #788c5d`
  - Comment `// palette unverified — G-B1 open` + philosophy quote in file header
  - `Theme` interface (bg, bgSubtle, bgStripe, text, textMuted, border, accentPrimary, accentSecondary, accentSuccess, selection, focus)
  - `lightTheme` and `darkTheme` maps derived **only** from `palette` values (no new literals) — light bg #faf9f5/text #141413, dark bg #141413/text #faf9f5, etc.
  - `themes` registry + `cssVars` map (`--tablify-*`) + `applyTheme(root, 'light'|'dark')` — toggles `tablify` + `tablify--light|dark` on root, sets CSS vars inline via `style.setProperty`, never touches `document.body`
  - `allTokensResolved()` helper for tests
- `styles.css` (repo root, auto-loaded by Obsidian) — plugin-scoped rules using only `var(--tablify-*)`, no hex literals. Example: `.tablify { background: var(--tablify-bg); color: var(--tablify-text); }`
- `tests/ui/theme.test.ts` — 7 tests (jsdom environment):

  - every token resolves in both themes + keys equal
  - themes derived only from palette values
  - automated grep finds no `#[0-9a-fA-F]{3,8}` outside `tokens.ts` (walks `src/` + `styles.css`)
  - `applyTheme` toggles class + sets vars, does not pollute global
  - T-M 4-combo layout identical (`theme-light|dark` × `tablify--light|dark`, 5 rows × 3 cols)
  - perf theme switch p95 <100 ms (proposed)
- `package.json` + `package-lock.json` — added `jsdom` devDependency for T-M jsdom tests (36 new packages)

## Coverage notes

- Palette stays “unverified” per G-B1 — comment in `tokens.ts` + evidence marks unverified; P3-11 will re-verify contrast and G-B1 closure
- Dark theme `bgStripe` uses `palette.midGray` (same as `bgSubtle`) to stay within the 7 palette values — no new hex. If design later needs a distinct dark stripe, it must be derived via opacity over `palette.midGray` rather than a new literal, to keep the “only tokens” rule
- `styles.css` contains zero literals by design — all colors flow via `var(--tablify-*)` set inline by `applyTheme`. Future grid components must continue to read `var(...)` only.
- `applyTheme` is the single entry point for theme changes; no global CSS import changes Obsidian theme

## Decisions

- Vanilla JS theme (no library) — `applyTheme` is 10 lines, no dependency, mobile-safe
- CSS variables set inline on root rather than hard-coding in `styles.css` — keeps `styles.css` literal-free so the “no color literal” T-U stays green when grid components are added
- jsdom added (was not in repo) — required for T-M DOM tests (`document.createElement`, `classList`, `style.getPropertyValue`). Alternative was Happy DOM but jsdom is the Vitest default
- Palette use-as-is per your 2026-10-09 answer (`use_as_is`) — values copied verbatim, lower-case as in branding.md
