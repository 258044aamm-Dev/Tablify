## Correction — two Obsidian variables leaked into the grid (SAD-69 D)

**Commit:** `f1caa8f`.

This step established that the grid's colours come from `applyTheme` via `var(--tablify-*)`, so
the table is **independent of the host Obsidian theme**. Two inline values broke that, and both
were introduced after this evidence was written:

| location | was | now |
|---|---|---|
| `GridView` header background | `var(--background-primary)` | removed — comes from `styles.css` (`.tablify__header { background: var(--tablify-bg-subtle) }`) |
| selected-cell outline | `var(--interactive-accent)` | `var(--tablify-selection)` |

The header case was the worse of the two: an inline value outranked the stylesheet rule, so the
header followed whatever Obsidian theme was active rather than the plugin's. It also had to stay
opaque, since it hides rows scrolling underneath it.

`tests/ui/tokensNoObsidianVars.test.ts` now guards this. It mounts a `GridView`, selects a cell,
and walks every descendant's inline style, failing if any `var(...)` is not a `--tablify-*` one;
it also asserts the header sets no inline background at all, so the stylesheet rule is what
wins. It covers the rendered grid, not `styles.css` as a whole — a stray Obsidian variable in a
static rule would not be caught by it.
