## Objective

Exports match what the user sees, in CSV, XLSX, and Markdown.

## Deliverables

- `src/io/export/view.ts` — scope resolution: current view (saved sort, visible fields, column order, optional query) or full table; `cellText()`; stable multi-key `sortRows()` with nulls last.
- `src/io/export/csv.ts` — RFC 4180 writer: quotes fields with `, " CR LF`, doubles `"`, CRLF line ends, UTF-8 BOM.
- `src/io/export/markdown.ts` — GFM table writer: `\` → `\\`, `|` → `\|`, CR/LF/CRLF → `<br>`.
- `src/io/export/xlsx.ts` — write-excel-file 1.4.30 (candidate A from P4-02). Numbers as numbers, checkbox as booleans, dates as real date cells (`yyyy-mm-dd`), everything else as text. Each cell is `{ value }` (P4-02 F4).
- `src/io/export/exporter.ts` — builds content in memory, then one `create`/`createBinary`. Collision rule shared with import (`Name 2.csv`, never overwrite).
- `src/commands/export.ts` — "Export table (CSV, Excel, Markdown)" command: modal with format and a "Full table" checkbox (default off = current view). Wired in `src/main.ts`.
- `src/io/import/importer.ts` — `candidatePath` and `pickFreePath` take an extension (default `tablify`). Import behaviour is unchanged.
- `package.json` / `package-lock.json` — `write-excel-file@1.4.30` added as a pinned runtime dependency.
- Tests: `tests/io/export.markdown.test.ts` (11 escape cases + round trip), `tests/io/export.csv.test.ts` (quoting + round trip through the P4-01 parser), `tests/io/export.view.test.ts` (scope, hidden fields, order, sort, filter, display text), `tests/io/export.e2e.test.ts` (T-D, T-I, failure, collision, PERF-7), `tests/io/export.fixtures.ts`.

## Bugs found and fixed during this step

1. **Currency and percent expectations.** The independent expectation used raw stored values (`1235`), but the display is `12.35` (minor units). The export was right; the expectation was wrong. Fixed the expectation.
2. **Percent fixture was out of range.** Percent is stored as a 0–1 decimal. The fixture stored 0–99. Fixed the fixture.
3. **Query syntax.** `Done = true` is an error in this query language (`Done:true` is correct). The export correctly refused the bad query.
4. **Collision test path.** The folder prefix was missing in the test's existing-file list. Fixed the test.
5. **Multi-select display** uses `, ` between names (display formatter). The test expectation was corrected to match. Option names that contain `, ` are ambiguous in CSV (see §7).
6. **T-I TZ label.** The test label first said the runner applied the TZ. It does not. Renamed, and ran the suite once per TZ through the environment variable.

## Guard change (P3-10 bundle budget) — OWNER DECISION

`tests/ui/fonts.test.ts` had a sanity guard: total bundle < 200,000 bytes (self-set in P3-10, not a spec requirement). The P4-02 XLSX libraries push the dev build past it.

- Dev `main.js` (committed, built by `npm run build`): **1,343,109 B**, total **1,415,481 B**. The inline sourcemap includes the source of the two XLSX libraries, which accounts for most of this.
- Production build (`node esbuild.config.mjs production`, minified, no sourcemap): `main.js` **201,817 B**. Total would be about 274 KB.
- Guard raised to **1,500,000 B** with the reason written in the test. The original limit is not met by the dev build.
- **Owner decision needed:** switch the release build to `production` (recommended for Obsidian releases; the committed `main.js` would then be minified), or keep dev and accept the current size.
- Pre-existing ordering: `npm run check` runs this test before the build, so it measures the previous build's output.

## 7. Known limitations (recorded for the owner)

1. **Current view does not include the live filter.** The grid's search and filter bar are runtime UI state; the file does not store them. The command exports the saved view (sort, visible fields, column order). The resolver accepts a `query`, so the grid can pass its live filter later. Until the grid is wired into Obsidian, "current view" is the saved view. Views: `views[0]` is used (no per-view picker in the UI).
2. **CSV formula injection.** Cells beginning with `=`, `+`, `-`, or `@` are exported unchanged. Excel and other spreadsheet apps may evaluate them on open. Escaping them would change the value and break the round trip, so this is not mitigated. Owner to decide.
3. **Display text.** CSV and Markdown contain display text: currency as `12.35` (no symbol), percent as `37%`, multi-select as `A, B`. Option names that contain `, ` are ambiguous in CSV.
4. **Checkbox** exports as `true`/`false` (not `✓`) so it re-imports.
5. **XLSX** exports text for currency, percent, and multi-select; numbers, booleans, and dates are typed.
6. **BOM.** CSV starts with a UTF-8 BOM so Excel reads non-ASCII text. The P4-01 parser removes it on read.
