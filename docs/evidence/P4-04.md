## Decisions made in P4-04 (recorded for owner review)

1. **First sheet only for XLSX.** Other sheets are ignored, and the notice says how many. Multi-sheet choice is not in the spec.
2. **First row is the header.** No option to turn it off in the UI (the `hasHeader` option exists in the builder only).
3. **Text cells keep their raw value** (no trimming). Whitespace-only cells count as empty and are stored as empty.
4. **Date-time values in XLSX that are not midnight become text**, so the time is never dropped silently. Integer Excel date serials are read as UTC midnight in every time zone tested (verified), so ordinary date cells import as dates.
5. **Strict inference (P4-03)** governs types. Any value that does not convert to its inferred type stops the import with an error.
6. **Import name** is the file name without extension, with `# ^ [ ] | : * ? " < > \` replaced by `-`.

## Bugs found and fixed during this step

- My first date rule accepted only UTC-midnight Dates. Tests with SheetJS-written dates failed in Dhaka and Los Angeles. Cause: SheetJS writes local-time, fractional serials, which real Excel files do not contain. Fix: fixture now uses integer serials with a date number format (how Excel stores dates). The rule stays UTC-midnight, verified in four time zones.
