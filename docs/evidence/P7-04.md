## Intentional contract change (recorded)

The v1 rule **"`sync` and `syncLink` must be `null`"** is **replaced** by "`null` or a validated structure".

- Malformed values are still rejected. Tests cover bad IDs, bad hashes, bad enums, duplicate record IDs, and non-boolean flags.
- Files with `sync: null` and `syncLink: null` (all existing v1 files) load and save unchanged. The existing `samples/v1/*` files still pass.
- Two existing tests asserted the old rule. They were **updated, not weakened**:
  - `tests/schema.test.ts`: `describe('syncLink and sync must be null in v1')` now checks that the valid sync sample is accepted and that malformed sync values are rejected.
  - `tests/format/format.test.ts`: `it('rejects non-null syncLink')` now checks that a valid `syncLink` is accepted and a malformed one is rejected.
  - `synced.tablify` is added to the schema test's valid-sample list.
