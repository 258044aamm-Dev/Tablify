# SAD-304 — An interactive, star-based rating

**Issue:** [SAD-304](https://linear.app/sad-mod/issue/SAD-304/rating) (Feature + Improvement, P2)
**Plan:** [`docs/plans/sad-304-rating-plan.md`](../plans/sad-304-rating-plan.md)
**Status:** delivered; **In Review**

## What the owner asked for

1. Stars instead of a bare number, with the number beside them, filled up to the value and
   **partially filled** for fractions (0–5, including 1.5, 2.5, 3.7, 4.5).
2. Click a star to rate, with hover, focus, selected and disabled states, keyboard and
   screen-reader support, on desktop and touch.
3. Keep the numeric value in the existing model, validate the range, and persist through the
   existing storage path.
4. Reuse the architecture, add no unnecessary dependency, keep every existing feature, and test
   whole values, decimals, selection, persistence and boundaries.

## The four decisions behind the shape

| Question | Answer |
|---|---|
| Range | The field's **Max** is the scale (5 when unset, up to 10). The type accepts 0–10 so 10-star fields and their data keep working. |
| Where the stars live | Click in the cell (whole stars) **and** a panel (halves, exact values, keyboard). |
| Fractions | Half-star zones plus a numeric field, two decimals. |
| Airtable | Round on push, and say how many ratings were rounded. |

The storage type did not change, so **no `formatVersion` bump** and old files read exactly as
before. `null` (no rating) and `0` (zero stars) stay distinct.

## How the stars are drawn

Each star is two copies of the same Font Awesome glyph in an 11 px box: the base in the placeholder
ink, and the accent-ink fill clipped to `width: <fraction>%`. One asset, every fraction, no
half-star image. `--on` still marks a full star; `--partial` is new.

## The panel

Same card, anchoring and dismissal as the date and phone panels (`createPanelCard` +
`anchorPanel`; a press outside or **Escape** dismisses). It **drafts**: nothing reaches the store
until **Done**, and an untouched panel hands the stored value back, so opening and dismissing a
cell writes nothing.

- Star row: `role="slider"`, `aria-valuemin/max/now`, `aria-valuetext="4.5 out of 5 stars"`.
- Pointer: left half of a star = `x.5`, right half = `x`; drag scrubs; the caption follows.
- Keyboard: `← ↓` −0.5, `→ ↑` +0.5, `PageDown/PageUp` ±1, `Home`/`End`, `Delete` clears, digits
  set, `Enter` commits.
- Numeric field: `inputmode="decimal"`, comma accepted, two decimals, `0…Max`; invalid text shows
  the hint, sets `aria-invalid` and disables Done.
- **Clear** empties; a press outside keeps a valid change and discards an invalid one.
- Read-only ratings (an Airtable field flagged read-only) draw no clickable stars and open no panel.

## Airtable

`localToRemote()` rounds a rating; `fractionalRatingCount()` counts the fractional cells a push is
about to send; `sync/engineTypes.ts` carries `roundedRatings` and `summarize()` appends
`N rating(s) rounded for Airtable`. Because the push records the hash of the **server's echo**, the
next sync does not read 5 back as a remote change. The file keeps `4.5`.

## What deliberately did not change

- Copy, CSV/XLSX export, search, sort and grouping read the number, as before.
- Group headings still read `4.5/5`.
- Other field types, panels, menus and the file format are untouched.
- The inline text editor for rating is gone — the panel's numeric field replaces it (the panel is
  the only editing surface, as for phone and date).

## Manual checks worth repeating on a device

The automated suite runs in jsdom, which has no layout, no pointer capture and no screen reader.
These are the checks a device still owes:

1. A 5-star field in a light theme and in a dark theme: the partial star is visibly partial and the
   number matches.
2. A 10-star field: ten stars, half steps still land where the pointer is.
3. Mouse: click star 4 → `4`; click it again → no undo entry; one **Undo** returns the previous
   value.
4. Touch at phone width: tap a star rates; a long press still opens the context menu; the panel's
   stars are comfortable to hit.
5. Keyboard only: **Enter** on a cell, arrows through halves, type `3.7`, **Enter**; **Escape** in
   a fresh panel writes nothing.
6. A screen reader announces the slider's value and range (`4.5 out of 5 stars`).
7. A linked Airtable table: push a row holding `4.5` → Airtable shows `5`, the sync message says
   one rating was rounded, a second push sends nothing.

## Known limits

- The E2E editing matrix (`npm run test:fields`) was updated (rating now opens the panel; the
  display checks read the number) but **not executed here** — Playwright and a browser are not
  part of this workspace.
- The stars inside a cell are pointer-only by design; keyboard and screen-reader users go through
  the panel, which is one **Enter** away.
- `convertCell()` — importing into an **existing** rating column — still follows its old path; this
  issue did not widen it. Inferred new columns have no rating rule, as before.
