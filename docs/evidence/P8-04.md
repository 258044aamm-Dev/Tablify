## Implementation decisions where the spec is silent

These are for the owner to confirm.

1. **Links resolve by table ID and row ID only.** Names, file paths, and row labels are display only. Renaming a file or a target row does not break a link.
2. **Broken links are never removed.** Deleting a target row or a target file leaves the reference in the source. The picker lists it as "Missing" and keeps it checked, so the user decides.
3. **The picker edits one table.** Each link field has a default target table. The picker lists that table's rows. Links into other tables stay as they are on save, and the picker says how many there are. Editing those needs a second picker, which is not in this step.
4. **Open tables publish live state.** An open table's unsaved edits resolve for links at once. The index does not read the disk for a file while a view has it open.
5. **Duplicate table IDs.** Obsidian's own file "Duplicate" copies the file, including its table ID. The Tablify "Copy table" command gives a new ID. For a duplicate ID, the first file by path is used, and the integrity check reports both paths.
6. **Paste is refused for link cells.** Pasted text cannot name a row ID. "Choose linked rows…" is the way to change links.
7. **Sync.** Link fields stay out of Airtable (P8-03 rule, unchanged).

## Known limits (not fixed in this step)

- **Sort, filter, copy, and export of a link column use the count** ("2 linked"), not the names. The grid shows names, but the sort and filter code calls the type's `format`, which has no vault access. A name-based sort would need the index in the query layer. Owner decision if wanted.
- **Not visually checked in a browser.** The picker layout, the broken-link underline, and the integrity modal were checked through unit tests in jsdom, not by eye. Look at one table with a link column before release.
- **Embedded tables** show names and markers, but editing links needs the full table view.
- **Mobile** was not tested on a device. The picker rows are full-width with a 44 px minimum height.

## Not in this step

- Name-based sort and filter for link columns (see limits).
- The Task C gate (`docs/gates/phase-8.md`).

## Addendum: duplicate table IDs (follow-up)

- **Finding:** Obsidian's native file Duplicate copies the file text, so the copy keeps the original `tableId`. The spec's assumption (R-D11) did not hold for that path. Tablify's own Copy command already gives a new ID.
- **Change:** `src/links/reissueTableId.ts` (pure): `reissueTableIdText` changes only `tableId`; `decideReissue` decides reissue, keeps-id, not-duplicated, or open. `src/menus/fileMenu.ts`: item "Give this copy a new table ID", shown only on a copy in a duplicate group. It re-checks the index and refuses while the copy is open in a table tab.
- **Tests:** `tests/links/reissueTableId.test.ts` (7 tests: only `tableId` changes; owner kept; open refused; three-file case). Full check at this commit: exit 0, 80 files, 1,234 tests, 119 warnings (baseline).
- **NOT RUN in Obsidian:** the menu item on a real duplicate, the notices, and the view refresh after the write.
