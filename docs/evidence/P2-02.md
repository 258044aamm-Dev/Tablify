## Objective

Compile a `QueryAST` (produced by `src/query/parse.ts`) into a predicate over rows via the field registry. Type mismatch (e.g. `:>5` on a text field) must be a query error with precise position, not an empty result. Must pass 30 hand-written filter cases, 10k random-query differential against a naive reference over FX-M with 0 mismatches, and PERF-2 (<200 ms p95 on 1k rows).

## Deliverables

- `src/query/evaluate.ts` — pure filter engine (no Obsidian): `compilePredicate(ast, fields) → predicate | QueryError` and `evaluateQuery(ast, rows, fields) → {ok, rows, matchedIds}|{ok:false,error}`. Field lookup is case-insensitive via `Map<lower name → FieldDefinition>`. Helper `offsetToLineCol` reports line/column. Type families:
  - text (`text`,`long_text`,`url`,`email`,`phone`,`attachment`) — allowed ops `eq` (+ comma multi = containsAny), `contains` (`~`), `empty`; `not`/`gt`/`lt` → `QueryError`.
  - single_select — `eq` (1 = exact ID, 2+ = isAnyOf), `not` (`!` = single resolved ID, unknown option → match-all per spec), `empty`; `contains`/`gt`/`lt` → error.
  - multi_select — `eq` (containsAny via resolved option IDs; unknown options ignored; empty list → no-match), `empty`; `contains`/`not`/`gt`/`lt` → error.
  - checkbox — `eq` (accepts `true`/`false`/`yes`/`no`/`1`/`0`/`✓`/`checked`/`unchecked` case-insensitive, comma multi = isAnyOf), `empty`; else → error. Invalid boolean literal → `QueryError`.
  - number family (`number`,`currency`,`percent`,`duration`,`rating`,`auto_number`) — via field-type registry `getFieldType(type).parse` for value normalization (e.g. currency `$12.34` → 1234 minor, percent `50%` → 0.5, duration `1h30m`). Allowed ops `eq` (single or `a,b` OR), `gt`/`lt`, `empty`; `contains`/`not` → error. Empty string cell never matches number/date eq; invalid numeric literal → `QueryError`.
  - date family (`date`,`date_time`,`created_time`,`modified_time`) — `eq` exact (date-only normalized to `YYYY-MM-DD`, date_time via `Date` ISO), `gt`/`lt`, `empty`; else → error. Invalid date → `QueryError`.
  - Unknown field (`fieldName` not in registry) → `QueryError` with `Unknown field: "<rawFieldName>"` and position/line/col from `term.position`.
  - Empty handling: `isEmptyCell` (null/undefined/''/[]) and `:empty` keyword plus `field:` (empty string eq) are the only matches for empty.
  - Predicates are closures over `FieldDefinition` id; evaluation is a single linear scan `O(rows × terms)` with short-circuit AND.

- `tests/query/fixtures.ts` — deterministic PRNG `mulberry32`, helpers `randomInt`/`randomChoice`, hand fixtures (`HAND_FIELDS` 7 types covering primary text, single/multi select, number, date, checkbox, long_text + `HAND_ROWS` 5 known rows) and synthetic generators `generateFXM` (12 cols × 1k rows, seed 42, covers all types), `generateFXS`/`generateFXL` (10k rows). IDs `row_1`…; fields use stable option IDs.

- `tests/query/reference.ts` — naive reference evaluator (`referenceEvaluate`) — direct `for row → for term → if/else` per type, same empty/option/number/date semantics as `evaluate.ts`, but without compilation. Includes `validateTermType` pre-check so type/parse errors are not masked by earlier-term short-circuit (parity with compiled eager check). Test-only helper, not shipped.

- `tests/query/evaluate.test.ts` — 48 tests: 30 hand-written cases over `HAND_ROWS` (empty, case-insensitive single/multi, exact vs containsAny vs `~contains`, numeric `> < =` with OR, date `>`/`<`, checkbox `true`/`false`/`yes`, empty keyword, multi-term AND, quoted names), 13 type-mismatch error cases (text `>`, single `~`, multi `!`/`>`, number `~`, date `~`, etc. → `ok:false`), 5 unknown-option cases (single unknown → no-match, `!bogus` → match-all, multi unknown → no-match).

- `tests/query/differential.test.ts` — T-D + PERF-2: (1) 10k seeded random ASTs over FX-M (seed `0xabc123`) — `evaluateQuery` vs `referenceEvaluate` comparison on `ok` and `matchedIds` — 0 mismatches (includes ~10% forced type-mismatch and ~5% invalid numeric terms to exercise error paths); (2) 5k random query strings via `printQuery → parseQuery → evaluate` vs reference — 0 mismatches; (3) PERF-2 on FX-M 10 × `Status:Todo Count:>5` → median 0.04 ms p95 0.05–0.18 ms (<200 ms proposed, <500 ms sandbox hard ceiling); (4) FX-L 10k rows informational → 1.6–2.3 ms.

## Coverage notes

- Empty semantics: `isEmptyCell` (null/undefined/''/[]) is the single source; `:empty` and `field:` (empty string eq) both map to it. Number/date `eq` with `''` is also treated as empty (matches only empty cells).
- Option resolution: `resolveOptionId` lowercases both name and id; single `eq` unknown → no-match, single `not` unknown → match-all (spec: negating a non-existent selection matches every row), multi `eq` filters unknown IDs and returns no-match if none resolve.
- Numeric parsing: delegates to `getFieldType(type).parse` so currency/percent/duration/rating use the same registry as table storage (e.g. `Score:>5` on a `number` field compares numeric `cell` values, `Cur:$12.34` would compare minor units). Reference's `parseNumeric` mirrors the same rules for differential parity.
- Date gt/lt/eq use `new Date(raw).toISOString()` normalization; date-only (`type:'date'`) compares `YYYY-MM-DD` strings, date_time compares epoch ms; empty string out-of-band already handled.
- Type-mismatch errors carry `position` = `term.position` (offset into `rawInput`) and `line`/`column` via `offsetToLineCol`, matching P2-01 error contract.
- Module boundary: `src/query/evaluate.ts` imports only `src/query/parse.ts` types and `src/model/fieldTypes.ts` + `src/model/types.ts`; zero Obsidian imports.

## Decisions

- Hand fixtures include 7 fields (not 12) to keep the 30 cases readable; FX-M (12 fields) is used for differential/perf to cover every `FieldType` including `currency`/`percent`/`duration`/`rating`/`auto_number`/`attachment`/`email` etc.
- Reference pre-validates `validateTermType` before row loop so a later term's type error is not masked by an earlier term evaluating to `false` for all rows (e.g. `Doc:Bob Tags:>urgent` where `Doc:Bob` is false for every row would otherwise hide the `Tags:>urgent` error). This matches the compiled engine's eager `compileTerm` error.
- Random AST generator forces ~10% type-mismatch terms and ~5% invalid numeric/date literals so the 10k set exercises both `ok:true` and `ok:false` paths; `forceMismatch` picks op `gt`/`lt`/`not`/`contains` on incompatible families.
- Performance samples use `performance.now()` 10 times after warm-up; p95 is median of sorted times at 95th percentile index. Sandbox threshold relaxed to `<500 ms` to avoid flake on oversubscribed CI while still logging true p95 for evidence; hardware gate applies on self-hosted runner per `guidelines.md PERF-2`.
