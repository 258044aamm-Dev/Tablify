# SAD-356 — Attachment field: pick a file, or enter a URL / path

**Issue:** [SAD-356](https://linear.app/sad-mod/issue/SAD-356/attachment-field) (Bug, P2)
**Plan:** [`docs/plans/sad-356-attachment-field-plan.md`](../plans/sad-356-attachment-field-plan.md)
**Status:** delivered; **In Review**

## What the report said, and what was actually wrong

> "Currently, when a user creates an Attachment field and taps a cell to add an attachment, the file
> picker does not open."

Verified on `9ff1a61` before any change: `grep -rniE "type=[\"']file|FilePicker|showOpenFilePicker" src/`
returned **0 hits**. There was no picker to open. An Attachment cell reached
`TableView.startEdit` → `openCellPanel` → `AttachmentPanel`, which built a single
`<input type="text">` for a vault-relative path and focused it — a keyboard on a phone and no way to
browse the device. The prototype the plugin mirrors said the same thing in its hint: *"File picking is
Obsidian-side — simulated here."* (`Prototype/script.js:1006`).

## The owner decisions this shipped against

| # | Question | Answer |
|---|---|---|
| D1 | What does "Choose a File" store? | The picked file is **copied into the vault**; the cell stores the vault-relative path |
| D2 | Which cells get the menu? | **Empty** cells open the menu; a filled cell keeps today's panel **plus** a *Choose a file…* button |
| D3 | URL strictness | `http(s)://` and `data:image/*` are remote values (no vault check); everything else is a vault path (checked as before) |
| D4 | A platform that refuses a picker | Fall back to the path/URL entry, with a message |
| D5 | Size cap on the imported file | **None** (no cap, no `arrayBuffer` guard) |
| D6 | Trigger gesture | Unchanged: double-click / Enter / second tap |
| D7 | Name of the copied file | The file's own name; Obsidian numbers collisions |
| D8 | Reachability probe for a URL | None — the value is stored as typed |
| D9 | Where the commits land | `main` |

## How it works

```
empty Attachment cell →  AttachmentMenu  ── Choose a file… ──────────┐
   (dblclick/Enter/2nd tap)             └─ Enter a URL or file path… ─┐│
                                                                      ││
filled Attachment cell → AttachmentPanel (+ Choose a file…) ──────────┘│
                                                                       │
                        <input type="file"> → File ────────────────────┘
                              ↓
        FileManager.getAvailablePathForAttachment(name, tablePath)   [Obsidian's folder, deduped]
                              ↓
        Vault.createBinary(path, await file.arrayBuffer())
                              ↓
        session.setValue(rowId, fieldId, path) + afterChange()      → one undo step, one save
                              ↓
        Notice "Saved to <path>"
```

`pickFileFromDevice()` answers with `file`, `cancelled` or **`unavailable`**; `unavailable` (a WebView
that never opens a chooser) shows a message in the menu and leaves the path/URL route one tap away.

## Two bugs the change surfaced (found by running, not by reading)

1. **`normalizeAttachmentPath` mangled URLs.** It collapses `//` (right for vault paths), so the first
   URL entered in the panel was stored as `https:/example.com/a.png`. `onAdd` now stores remote values
   verbatim; the case is pinned by *"stores a URL as typed — no vault check, no Save anyway"*.
2. **`setBusy(null)` left the "Opening your file picker…" label on screen** after a cancel. The message
   line is now one channel: the busy label clears when the work ends, and a failure message is set
   after that.

## Visual parity

The new `Choose a file…` button and status line are **plugin-only rows** — the prototype has no
equivalent, exactly like the plugin-only `.tablify__attach-warn` row. They are therefore not part of
`tests/visual/capture-panels.ts`'s `parts`, and both screens' notes say so. `npm run check` does not run
the capture script; re-run `npx tsx tests/visual/capture-panels.ts` before a release and expect the
attachment crops to be taller by that one row.
