## Objective

Choose an XLSX reader and writer that work on mobile and do not use Node APIs. Decision record: `docs/decisions/xlsx.md`.

## Deliverables

- `docs/decisions/xlsx.md`: decision, measurements, findings F1–F7, accepted limits, NOT RUN list.
- `spike/xlsx/` (**not shipped**; outside `src/`, not in the build): `run-spike.mjs` (harness), `src/candA.mjs`, `src/candB.mjs`, `src/stub.mjs`, `results.json` (raw numbers).
- `scripts/gen-fixtures.mjs`: deterministic fixture generator. Writes `samples/fixtures/fx-xlsx.xlsx`, hash in `samples/fixtures/HASHES.json`. `--check` verifies the hash.
- `samples/fixtures/fx-xlsx.xlsx` (FX-XLSX: 5,000 rows × 10 columns; Excel dates; booleans; formula cells with cached values; merged cell; three sheets; text with commas, quotes, and leading/trailing spaces).
- Root devDependency `xlsx@0.18.5`: **test-only** fixture writer. Not imported from `src/`.

## Procedure

1. Built both candidates for the browser platform with esbuild (minified ESM) and measured bundle size (raw and gzip) against an empty stub.
2. Scanned each bundle for Node-only imports (fs, path, stream, zlib, crypto, child_process, `node:*`).
3. Read FX-XLSX with each candidate and compared every cell with the generator's known values (5,001 rows × 10 columns).
4. Timed the FX-XLSX read: 3 warm-up runs (not counted), then 10 measured runs. Median and p95 reported.
5. Round-tripped a 500-row table: each library writes, the other library reads it back (second-reader check).
6. Repeated the fidelity check under `TZ=Asia/Dhaka`, `TZ=America/Los_Angeles`, and UTC.

## Findings that change implementation (must be honored in P4-03..P4-05)

- **F1** Always read with `{ trim: false }`.
- **F2** Never use SheetJS `cellDates: true` for date values. Date handling must use UTC components. Covered by a TZ test in P4-03.
- **F3** write-excel-file writes an **empty sheet silently** when given plain values. Every export cell must be `{ value }`, and P4-05 must read every exported cell back to verify.
- **F4** No public sheet-name API in read-excel-file v8. Read once and select sheets by the `sheet` field of the result.
- **F6** Browser builds need `DOMParser`. Obsidian provides it; tests use jsdom.

## Deviations

1. Candidate B's fidelity check used `cellDates: true` (the common default). That setting causes F2. The alternative configuration (`cellDates: false`, manual conversion) was **not** measured. This is recorded as an open question, not a pass for B.
2. The spike harness (`spike/xlsx/run-spike.mjs`) is run from the repo root's `node_modules` for esbuild and jsdom.
