## What exists

- `src/sync/pull.ts`: pull. Fetch, plan, then apply. Clears undo.
- `src/sync/push.ts`: push. Changed rows only. Batches of 10. Row-level retry on batch failure.
- `src/sync/rules.ts`: the decision table. Pure function, one test per case.
- `src/sync/conflicts.ts`: keep local, keep remote, keep both. Refuses a stale resolution.
- `src/sync/autoCreate.ts`: plan and confirmed creation. Rebases the remote hash for new fields.
- `src/sync/values.ts`, `src/sync/hash.ts`: value conversion and SHA-256 (pure, no Node or DOM crypto). Hash checked against the standard vectors.
- `src/sync/engineTypes.ts`: report type and run bookkeeping.
- `src/model/tableStore.ts`: `setRowSync` and `setFieldAirtable`. Neither bumps `rev`.
- `src/model/tableSession.ts`: `getSyncLink` and `setSyncLink`. `toFile()` writes the current link, not a stale copy.
- `src/sync/airtableClient.ts`: `createField` (POST to the fields endpoint).
- `docs/sync-rules.md`: the decision table.

## Known risks and limits

- **Retry on ambiguous create.** `send()` retries 5xx and network errors for POST too. If Airtable applied a create and the response was lost, a retry can duplicate that record. This needs a live check and possibly a no-retry rule for creates.
- **Keep both** creates a duplicate in Airtable on the next push (documented in `docs/sync-rules.md`).
- **Local deletions** are reported and not sent to Airtable. Deleting remote records is not implemented.
- **Lint.** New engine files add about 37 warnings, all non-null assertions or `any` in test code. Errors: 0 after the unused-import fix. The baseline was 81 warnings.
- **Typecheck.** New `src/sync/` files add no `tsc` errors beyond the known class (`appendChild` against the mock augmentation), and none in the engine.
