## Decisions and deviations

1. **Change field type rule (no data loss).** The spec does not define conversion rules. A type is offered only when every non-empty value converts without error: format in the old type, parse in the new type, then validate. Otherwise the item shows the count of blocked values and does nothing. This is a conservative rule I chose; the owner should confirm it.
2. **Select and attachment types are not targets** in this version (select needs an option list; attachments have their own path). The picker shows them with a reason.
3. **Picker, not submenu.** The installed Obsidian typings have no `setSubmenu`. "Change field type…" opens a picker instead. A blocked type shows its reason and a notice if chosen.
4. **Reasons for disabled items** are shown in the menu title, e.g. `Paste (Nothing copied yet)`.
5. **Undo bumps revisions.** The existing store increments `rev` on every update, so undo of a cell edit also bumps `rev`. The "undo all restores the original" test compares ids, fields, views, and values, and ignores rev and timestamps.
