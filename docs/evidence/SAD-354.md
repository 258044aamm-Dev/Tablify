# SAD-354 — Rating field visual polish

**Issue:** [SAD-354](https://linear.app/sad-mod/issue/SAD-354/the-rating-field-doesnt-look-good) (Improvement, P2)
**Plan:** [`docs/plans/sad-354-rating-polish-plan.md`](../plans/sad-354-rating-polish-plan.md)
**Status:** delivered; **In Review**

## What the owner asked for

> The rating field does not look visually appealing. Improve its UI design, including layout, spacing, alignment, and visual hierarchy, to make it look cleaner and more professional while maintaining consistency with the application's existing design system and preserving current functionality.

No Figma supplied — plan was audit-driven against the app's own float-panel family (date, phone, select) and prototype grid.

## The four decisions behind the polish

| Question | Answer |
|---|---|
| Scope | **Both** cell + panel, desktop+mobile, light+dark (owner confirmed) |
| Reference | **Propose via audit** — benchmark date/phone/select panels, tokens, row-height variants |
| Constraints | **Major redesign allowed** but behaviour-preserving: no model/sync/query/format change, no new dep |
| Touch | Grow to satisfy coarse-pointer guidance, like date's 36→44px pattern |

## What changed visually, precisely

| | Before | After |
|---|---|---|
| Cell stars | 11px box, gap 2px, margin 6px | **12px** (10 small, 13 large), **gap 3px, margin 8px, padding 2px 0** |
| Cell label | 10px mono muted | **11px mono 500 text, tabular-nums, 0.5px baseline nudge** |
| Cell hover | scale 1.15, opacity .55 | **border pill-hover + bg-pill-hover, scale 1.08, preview 8% accent tint** |
| Cell empty | placeholder ink (#C5C1BE) | **faint ink (#B7B2AE/#6B7280) via `tablify__stars--empty`** — intentional empty, not disabled |
| Panel width | 248px (only panel smaller than PANEL_WIDTH 320) | **300px, max min(320, vw-24), coarse 340px** — matches date/phone family |
| Panel body | generic `dropdown-body` | **own `rating-body` 12px/10gap** like `date-body` |
| Panel header | none (stars+caption centered column) | **field name 12/600 Poppins · caption 11 mono** flex space-between |
| Panel track | bare inline-flex gap4 pad2/4 | **pill bg-capsule border-subtle radius10 pad8/10 min-h36, gap6, hover border** |
| Panel stars | 20px fixed | **22px (18px for scale 10 via data-scale), coarse 24/20** |
| Panel numeric | bare dropdown-input + orphan `/5` | **32px capsule bg-capsule border-subtle radius8 pad0/10, focus-within accent+ring, placeholder, scale suffix inside** |
| Panel hint | 15px min-h 11/15 muted | **14px Poppins 11/14 danger, margin -2px, stable** |
| Panel foot | space-between stretched | **flex-end grouped, padding10, same as phone foot** |
| Touch | none | **@media (pointer:coarse) grows stars 24/20, track 42px, field 38px, hit-area 6px** |
| Read-only | same look, no `data-rating-star`, cursor default | **tooltip adds · read-only (sibling to scale)** |

All tokens are existing `--tablify-*` (no hex literals), no new dependency, no formatVersion bump.

## How it stays isolated

- `src/views/grid/cellRender.ts`: only `faIcon('star',12)` + empty-class addition, no logic; `ratingScale`, `starFills`, `wireStarPreview` untouched.
- `src/views/grid/rating/RatingPanel.ts`: own `rating-body`, `data-scale`, `rating-field` wrapper, header with field name; all handlers (pointer halves, drag, arrows/page/home/end/del/digit/enter, outside-press keep/discard, COD-68 untouched) verbatim.
- `src/views/grid/GridView.ts`: one-line tooltip addition `· read-only` behind `canRate` guard.
- `styles.css`: only `tablify__stars*`, `tablify__rating*`, `tablify__star*` selectors — never touches date/phone/select/attachment/toolbar/grid geometry.
- Model/sync/query/format untouched — `ratingType` still 0…10 2dp, `localToRemote` rounding, `fractionalRatingCount` preserved.

## What deliberately did not change

- Copy, CSV/XLSX/Markdown export, search, sort, grouping still read the raw number (`4.5`), not stars.
- Group headings still `4.5/5`.
- Airtable push still rounds `4.5→5` with summary `1 rating(s) rounded for Airtable`; file keeps `4.5`.
- Keyboard table (arrows .5, page 1, home 0, end scale, del null, digit, enter) and AT `role=slider` + `aria-valuetext` identical.
- Other field types, panels, menus, validation rule UI untouched.

## Manual checks worth repeating on a device

1. 5-star light+dark: 4.5 → four full + half star, number 11/500, empty faint but visible, read-only tooltip says read-only.
2. 10-star: ten stars at 18px fit 300px, half steps land, no overlap.
3. Mouse: click star 4→4, click again→no undo entry, Undo restores.
4. Touch (phone width coarse): tap star rates, long-press row menu still opens, panel stars 24px comfortably tappable, numeric capsule 38px.
5. Keyboard: Enter → panel, arrows through halves, type 3.7→3.7, Enter commits, Escape fresh writes nothing.
6. Screen reader announces header field name + slider value `4.5 out of 5 stars`.
7. Row heights S/M/L: stars 10/12/13px, no clipping.
8. Airtable linked: push 4.5→5 with rounded message, second push silent.

## Known limits

- No new field-type option (icon/colour for rating) — separate issue if ever desired.
- `convertCell()` import into existing rating column still follows old path — out of scope as in SAD-304.
