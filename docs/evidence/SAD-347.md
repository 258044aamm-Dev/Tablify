# SAD-347 — Inline per-cell image rendering mechanism

**Issue:** [SAD-347](https://linear.app/sad-mod/issue/SAD-347/inline-per-cell-image-rendering-mechanism) (Feature + Improvement, P2)
**Plan:** [`docs/plans/sad-347-inline-cell-image-rendering-plan.md`](../plans/sad-347-inline-cell-image-rendering-plan.md)
**Status:** delivered; **In Review**

## What the owner asked for

1. **Field scope (`attachment_only`)**: Render inline images in existing `attachment` cells when the stored path or URL is an image (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.svg`, `.bmp`, `.avif`, `.ico`), keeping non-image attachments as paperclip chips, with zero schema or `formatVersion` changes.
2. **Cell visual layout**: Render a rounded inline image thumbnail alongside the filename inside `.tablify__chip--file.tablify__chip--image`, scaled to fit existing `small` (`28px`), `medium` (`34px`), and `large` (`40px`) capsule heights without altering virtual-row math or `cell.textContent`.
3. **Interaction & preview (`lightbox_and_panel`)**: Clicking the inline thumbnail opens a themed lightbox modal preview (`ImagePreviewModal`) of the full image; clicking the rest of the cell selects/edits normally, and `AttachmentPanel` also shows a thumbnail preview banner.
4. **Missing/broken image fallback (`paperclip_fallback`)**: If an image file is missing from the vault or fails to decode at runtime (`onerror`), gracefully fall back to the standard paperclip chip with the filename intact so the cell never looks broken or loses its text.
5. **Non-regression**: Must not break or negatively influence any existing features, tests, or CSS/ARIA invariants.

## The four decisions behind the shape

| Question | Answer |
|---|---|
| Field scope | Existing `attachment` field type (`attachment_only`). No new field type, no `formatVersion` bump, and no change to sort, filter, search, copy/paste, CSV/XLSX/Markdown import/export, or Airtable sync. |
| Visual layout | `.tablify__chip--file.tablify__chip--image` renders a `16×16` (`small`), `20×20` (`medium`), or `26×26` (`large`) `object-fit: cover` thumbnail beside the path text node, trading vertical capsule padding via `.tablify__cell--attachment > .tablify__capsule`. |
| Interaction & preview | `button.tablify__chip-thumb-btn` stops propagation on click and opens `ImagePreviewModal` (`dressProtoModal(..., { icon: 'paperclip', size: 'xl' })`); clicking the rest of the cell selects/activates normally; `AttachmentPanel` shows `.tablify__attach-preview` + `.tablify__attach-row-thumb`. |
| Fallback | `resolveAttachmentImageUrl` checks `vault.getAbstractFileByPath(path)` before calling `vault.getResourcePath(file)` (or `vault.adapter.getResourcePath(path)`), returning `null` for missing files or folders; runtime `img` `error` removes the thumbnail and unhides `.tablify__chip-icon`. |
