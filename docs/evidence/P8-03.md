## Implementation decisions where the spec is silent

These are for the owner to confirm.

1. **Formula results are display-only.** They are computed from the cells and overlaid on copies of the rows. Grid, sort, and filter read the same values, and the file never stores them.
2. **Errors show as text with a tooltip.** The cell shows the code (`#DIV/0!` and so on). The reason is in the tooltip, and the cell gets an error class. The error colour uses the accent token, since the palette has no error colour and adding one would widen the theme tests.
3. **Formula in the change-type picker.** "Formula" appears there, disabled, with the reason "created with Add field". This keeps the add-field and change-type lists identical, which an existing test enforces.
4. **Syntax error vs other errors.** A syntax error is refused when the formula is saved. Name errors and cycles are saved and shown on the cell, so the user can fix them in place.
5. **Sync.** Formula and link are never written to Airtable. They are skipped in auto-create with a reason, and the Airtable read path returns null for them.
6. **Link in P8-03.** Read-only, with a minimal type and a count display. Link editing and chips are P8-04.
