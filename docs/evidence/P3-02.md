## Objective

Each field type can be edited, validated, and saved through a command. Enter commits, Escape cancels, blur commits, invalid keeps editor open.

## Deliverables

- `src/views/grid/editors/index.ts` — pure + DOM:
  - `isReadOnly(field)` — true for `auto_number`, `created_time`, `modified_time` or `getFieldType(...).readOnly`
  - `parseInput(field, input)` — uses `getFieldType(type).parse` + `validate`; distinguishes empty (`''` → null) from invalid (`'notANumber'` → null but input non-empty → error)
  - `createEditor(field, row, store, stack, onDone)` — returns `HTMLElement|null` (null for read-only). Creates `<input>`/`<textarea>`/checkbox per type, handles `compositionstart/end` (IME), `keydown` Enter/Escape, `blur` commit, sets `aria-invalid` + `title` on error, calls `createEditCellCommand` via `stack.execute` only on valid non-equal value
  - `commitValue(field, row, input, store, stack)` — headless helper for tests/toolbar, same validation + command path
- `tests/views/grid/editors.test.ts` — 8 tests (jsdom):
  - read-only types have no editor
  - parseInput per type (text ok, number invalid → error, checkbox invalid → error)
  - commitValue writes via command and undo restores
  - Escape leaves file unchanged (spy onDone(false))
  - invalid input keeps editor open, `aria-invalid=true`, no write
  - Enter commits valid
  - each type commit calls command path (spy on `stack.execute` for text/number/checkbox/date/single/multi/url/email)
  - commit <50 ms on FX-M (proposed) — 1k rows, median <1 ms

## Coverage notes

- IME composition: `isComposing` flag set on `compositionstart`/`end`; `Enter` during composition is ignored, `blur` during composition does not commit — documented in code, not fully automated in jsdom but unit-covered via flag logic.
- `parseInput` correctly treats `''` as empty (null) vs `'notANumber'` as invalid (error) — fixing `numberType` ambiguity where `parse` returns `null` for both. This matches P1-01 validation where `null` is allowed but invalid strings must be rejected in the editor.
- Read-only types use both hard list and `fieldType.readOnly` to stay correct if new system types are added.

## Decisions

- Editors are vanilla DOM, no framework — per P3-01 decision, keeps mobile-safe and matches grid shell.
- `createEditor` returns an `HTMLElement` that the grid will mount; for P3-02 the grid wiring is not yet fully integrated (grid will call `createEditor` on cell click in P3-03). The headless `commitValue` helper is the testable core and guarantees the command path is exercised without needing a full grid mount.
- Validation is delegated to `getFieldType(type).validate` so the editor never duplicates field rules — single source of truth.
