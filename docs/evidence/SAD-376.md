## What the report said

> "...when content exceeds the cell's width, the text is truncated with an ellipsis. While this
> keeps the table compact, it becomes difficult to read the full content, especially for long notes,
> descriptions or URLs. Improve the experience by showing **Expand** only when the content exceeds
> the configured limit ... The expanded content should preserve the table layout, remain readable,
> and be collapsible."

Owner decisions (asked, not assumed): trigger is a **global plugin setting** · hover gives **both**
an in-cell icon and a preview card, togglable · expanded is an **anchored floating panel** · touch
gets a **menu item** plus an **always-visible icon**, togglable · the ladder is cell hover → icon →
rest → card (copy + expand) → panel, with a click on the icon going straight to the panel · **on by
default at 80 characters** · any cell whose **displayed** text exceeds the limit, after formatting
and chips · card opens after **200 ms** · Copy goes to the **system clipboard only**.

### Two defects this found (both fixed in `ff43af1`, both now pinned by tests)

1. **The control painted as Obsidian's host pill** — 26 × 30 px, 1 px border, accent ink — because
   `.tablify__cell-expand` (0,1,0) loses to the host's `button:not(.clickable-icon)` (0,1,1). Fixed
   with the SAD-76 (RC-B) convention (element-qualified inside `.tablify`, resets fill, ink, weight,
   height, line-height, padding, border, radius, shadow). jsdom cannot see specificity against a
   stylesheet it does not load, which is why only the browser caught it.
2. **The expanded panel hung 28 px off a 390 px phone** — it was 360 px wide while `anchorPanel()`
   clamps against the shared `PANEL_WIDTH` (320): at x = 58 it ended at 418 px. Now exactly
   `PANEL_WIDTH`, with the CSS test asserting the imported constant instead of a literal.

### One assumption corrected

**Tab never reaches the in-cell control.** Measured trail: `.tablify__title` → … → the grid root,
after which Tab moves the **cell selection** (P5-02). The control is a real button and shows its
focus ring if focused, but the keyboard route is the cell menu's **Expand cell**, now pinned by its
own test (`tests/views/cellOverflowView.test.ts`) rather than assumed. Recorded in
`docs/accessibility/audit.md` §9.

## NOT RUN (environment limits, per `spec/guidelines.md` §0.1)

- **Real iOS / Android device** — no device in this environment. Runbook: on a phone the ⤢ sits in a
  long cell's corner at rest (touch-reveal on); tapping it opens the panel; long-pressing the cell
  offers **Expand cell**; the panel is fully on-screen in portrait; turning the touch-reveal setting
  off removes both the corner control and the menu item; no card ever appears from a finger.
- **VoiceOver / NVDA announcement of the new control and panel** — the ARIA contract is asserted
  (`aria-label="Show full content of <field>"`, `aria-haspopup="dialog"`, `role="dialog"` on the
  panel), but the spoken output is an owner T-I check like every other row in
  `docs/accessibility/audit.md`.

Blocks nothing in the automated gate; owner sign-off requested at review.
