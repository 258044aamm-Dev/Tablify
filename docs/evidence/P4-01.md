## Objective

Correct CSV parsing with a streaming-friendly design: RFC 4180 quoting, BOM strip, `,`/`;` delimiter detection, chunked processing with bounded memory.

## Deliverables

- `src/io/csv.ts`
  - `CsvStreamParser` — `push(chunk)` / `end()`; emits one record at a time via `onRow`. Memory is bounded by the longest record, not the file size.
  - `parseCsv(input, opts?)` — whole-string convenience wrapper that feeds the streaming parser in 64 KiB slices (same code path).
  - `detectDelimiter(text)` — `,` or `;` from the first record; tie → `,`.
- `tests/io/csv.test.ts` — 24 unit tests (RFC examples, CRLF, quoting, BOM, detection, errors, chunk-boundary invariance)
- `tests/io/csv.differential.test.ts` — T-D, 2 tests

## Parsing rules (as implemented)

1. Quoted fields with `"..."`; `""` inside a quoted field is one `"`.
2. Quoted fields may contain `,`, `;`, CR, LF.
3. Record ends: LF, CRLF, or a lone CR outside quotes. A CR followed by LF is one record end.
4. A UTF-8 BOM at the very start is removed and reported as `hadBom`.
5. Delimiter detection: on the first record, count unquoted `,` and `;`. The more frequent one wins. A tie (including none) gives `,`. A forced delimiter option skips detection.
6. Lenient: a `"` inside an unquoted field is kept literally (for example `5" screen`).
7. Strict errors (returned, never thrown): unterminated quoted field at EOF; text after a closing quote.
8. Ragged rows are returned as-is. The importer (P4-04) decides what to do with them.
9. Empty input gives 0 rows. A trailing newline does not add an empty row. A blank line in the middle gives `[""]`.

## Deviations and findings

1. **csv-parse reference quirk (found during T-D).** With default options, `csv-parse` 5.6 rejects some valid RFC 4180 files when a quoted field follows a CRLF (for example `x\r\n"b";"x"\n` with delimiter `;`). The differential test therefore sets `record_delimiter: ['\r\n', '\n']` on the reference. The generator never emits a lone CR, so this does not hide any case in scope. Our parser accepts those files as valid.
2. **FX-CSV-RFC fixture file not generated.** The RFC 4180 and edge-case examples are inline in `tests/io/csv.test.ts` instead of `samples/fixtures/`. The fixture-generator script will be added with FX-S/FX-M in P4-04. Recorded here as a deviation.
3. **Mobile timing (PERF-5 on device) NOT RUN.** No mobile device in sandbox. Owner to record on iOS/Android before the P4 gate.
4. **Lone CR is a record separator.** RFC 4180 does not define a lone CR. This is an explicit choice (rule 3 above), recorded here so reviewers can challenge it.

## Assumptions carried forward

- G-A5 (date parsing depends on locale): not in scope for P4-01. Applies to P4-03.
- Delimiter detection is count-based. Files where the first line is genuinely ambiguous (for example `1,5;2` European decimals with no quotes) can be detected wrong. The user can force the delimiter; P4-04 will expose that option. Recorded as a known limitation.
