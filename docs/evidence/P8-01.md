Decisions taken at approval and applied in the spec:

- D-O1: the Airtable-like function set (54 functions), not the smaller default.
- Date and time functions use the viewer's local time zone. Golden cases run in `Asia/Dhaka` so datetime results are stable.
- Formula results are not stored in the file.
- A formula that reads a link field gives `#VALUE!` in v2 (§12 item 2).

## Verification (carried from the engine step)

The golden cases were run against the engine in P8-02. All 204 pass in UTC and in `TZ=Asia/Dhaka`. See `docs/evidence/P8-02.md`.

## Open items

- **Field rename (§12 item 1).** The spec says renaming a field rewrites matching `{references}` in the table's formulas, as one undoable command. The app has **no field-rename feature** yet, so there is nothing to hook this into. The rule is accepted but not built. It must be built with any future field rename. Until then, renaming a field by editing the file leaves formulas with `#NAME?`.
- **Stale status note fixed.** `docs/formula-spec.md` §11 said the cases had not been run. P8-02 ran them. The note now says so.
- **Cycle timing.** The spec says cycles are detected at save time. The implementation detects them when a formula is set or a dependency changes, and shows `#CYCLE!` on the cell. This matches the approved P8-03 behaviour (decision 4 in `docs/evidence/P8-03.md`).
