## Objective

View settings save and reload exactly, and never crash when a referenced field no longer exists. Validate on load: unknown field IDs ignored with warning, not error. Reject hiding the primary field (R-D13).

## Deliverables

- `src/model/types.ts` — extended `ViewDefinition` with `columnOrder: string[]` (ordered column IDs) and `warnings?: string[]`. `columnOrder` is the explicit column reorder; `warnings` records non-fatal normalization messages. `frozenColumns` now 0..fields.length (was 1..); `rowHeight` unchanged.
- `src/model/view.ts` — pure module (no Obsidian): `validateView`, `normalizeView`, `createDefaultView`, `cloneView`, `sanitizeViewsForSave`. Single source for sort/groupBy/hidden/columnOrder/columnWidths/frozenColumns/rowHeight validation. All warnings are strings; errors only for primary-hidden (R-D13).
- `src/format/parse.ts` — now normalizes views on load via `validateView`: unknown field IDs stripped with warning, missing `columnOrder` derived from field order, primary-hidden auto-corrected with warning for load robustness, unknown keys preserved.
- `src/format/serialize.ts` — now calls `sanitizeViewsForSave` before ordering, so saved files never contain dangling field IDs. `VIEW_KEYS` extended to include `columnOrder` and `warnings`.
- `tablify.schema.json` — `view` definition: `frozenColumns` minimum 0 (was 1), added `columnOrder` (array of strings, optional for backward compat) and `warnings` (array of strings, optional). Existing samples remain valid.
- `samples/v1/{empty,typical,edge}.tablify` — updated to include `columnOrder` (field order) and `warnings: []` so they validate against new schema and survive round-trip.
- `tests/model/view.test.ts` — 21 tests covering per-setting save/reload, deleted-field handling, R-D13, and extra edge cases.

## Decisions

- `columnOrder` addition (owner-approved `add_column_order` 2026-10-09) — guidelines says “column order and widths” are two keys; `FORMAT_SPEC.md` and `types.ts` previously had only `columnWidths`. This step adds `columnOrder` as required field in new files but optional in schema for backward compat (old files without it load with derived order).
- `warnings` stored inside `ViewDefinition` so the view itself records what was dropped — matches spec wording “warning recorded in the view”. It is optional and defaults to `[]`.
- `frozenColumns` minimum lowered from 1 to 0 to allow zero frozen columns (clamped range now 0..fields.length).
- `sanitizeViewsForSave` called from `serialize` ensures dangling IDs never hit disk; `parse` also normalizes on load for robustness.
