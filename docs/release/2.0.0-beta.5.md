# Tablify 2.0.0-beta.5 — Pickers the plugin draws, and a focus that lets go

- **Release date:** 2026-10-18
- **Tag:** `v2.0.0-beta.5`
- **Channel:** Pre-release
- **Minimum Obsidian version:** 1.14
- **File format:** unchanged (no migration; `formatVersion` rules are the same as beta.4)

## Highlights

Nine tickets ride in this beta, from the two popups the plugin now draws to the
highlight that finally lets go:

- **Date and date-and-time cells open a picker the plugin draws (COD-75).** The window
  that appeared before was Chromium's own calendar: unthemed (a white sheet in dark
  mode), cramped into the cell's 16 px capsule, with no **Today** and no **Clear** — on
  Android it was the operating system's dialog. The cell now opens the same anchored
  card the select and attachment cells use: a mono value field you can type or paste
  into, a Monday-first month grid with today ringed and the picked day filled, a `hh:mm`
  row with **Now**, and **Today / Clear / Done** underneath. Picking a day in a Date
  cell commits and closes; a Date and time cell waits for **Done**, and changing only
  the day **keeps the time to the millisecond**. Typing a time means whole minutes.
- **The field type list is the plugin's own (COD-76).** **Field type** in Add New Field /
  Modify Field was a native dropdown: one word per row, unreadable against a dark theme,
  and in Modify any type that would drop values simply was not there, with nothing saying
  why. It now opens a panel the plugin draws, under the row: a search box, the five
  groups, and for every type its icon, its name and one true line about it (*Money, shown
  to two decimals*), with the current type ticked and **↑ ↓ / Enter / Esc** working
  through it. In **Modify Field** a type that would lose values keeps its place, greyed,
  with the count and the reason (*12 values cannot convert to text*). The panel is 100 %
  theme-aware and flips above the row when the screen is short.
- **The focused cell now lets go (COD-77).** The capsule outline used to stay on a cell
  until something else was selected. A press anywhere outside the table — the toolbar,
  the title row, another pane, the workspace — drops it immediately, at press time; an
  open editor commits first, so nothing typed is lost. Presses inside the table, on an
  open picker panel, or on a menu or dialog keep the highlight, exactly as the prototype
  intends.
- **Cells show what their value means (COD-71, COD-73).** A Single select cell shows the
  option as a coloured chip and a Multi select cell one chip per value, instead of the
  internal option ids. A **Rating** cell is stars plus `4/5`; **Date and time** /
  **Created time** / **Last modified** show your local wall clock; **URL** / **Email** /
  **Phone** cells are clickable links; **Number** cells group their digits and sit right;
  an **Attachment** is one paperclip chip per file; **Long text** clamps to two lines.
  A **Checkbox** is a box you can click — one click, one undo step, clickable in embeds
  too. Only the rendering changed: sort, search, copy and export still read the stored
  values.
- **One window for a field (COD-69).** **Modify field…** opens the same window that
  creates a field, with every row filled in from the field: name, type, options,
  validation rules, formula with its live preview, and linked table. Select options are
  edited through *Manage options…* in that window, where renaming cannot be told apart
  from deleting and adding. Saving is still one undo step; a save that changes nothing
  adds no undo entry.
- **One click on another cell while editing selects it (COD-70).** The commit used to
  re-render the rows under the pointer, so the browser never delivered the click that
  selects a cell — a second click was needed. The press now finishes the edit and
  activates the cell itself. A checkbox toggles in that same click; an invalid value
  keeps the editor open with the cursor still in it.
- **Freezing now means one column, not a run of columns (COD-72).** The column-header
  menu no longer offers *Freeze column*; the single control is **Options → Freeze
  primary column**, greyed out with the reason on a pane too narrow to freeze (≤ 639 px).
  The primary column is always the first column, and a hairline divider plus a soft edge
  shadow mark where the frozen column ends. A table saved by an older build with several
  frozen columns opens with the primary column frozen and the rest scrolling normally.
- **The file menu's Tablify items are branded (COD-74).** Right-clicking a `.tablify`
  file showed *Open*, *Duplicate* and *Export* with no icons and nothing saying Tablify.
  The three items are now **Open Tablify Table**, **Duplicate Tablify Table** and
  **Export Tablify Table**, each with its own icon, and the table's tab carries the table
  glyph.

## Compatibility and known limitations

This release does not change the `.tablify` file format. Tables using formula or link
fields are still saved as format version 2 and cannot be opened by Tablify 1.0.2 or
earlier; update every device before using those fields. A table written by beta.4 opens
unchanged in beta.5 and the reverse is true as well — a downgrade only costs the new
pickers and the rendering.

Live Airtable and Obsidian runtime checks remain owner-run: the sync is tested against a
fake server, and the on-device behaviour of the two new pickers and the outside-tap
clearing is the manual checklist in `docs/evidence/` (COD-75, COD-76, COD-77 sheets).

## Installing on a device

1. Download the three assets above from the release page.
2. Put them in `<vault>/.obsidian/plugins/tablify/`, replacing the existing files.
3. In Obsidian: **Settings → Community plugins**, then disable and re-enable **Tablify**
   (or reload the app) so the new `main.js` is loaded.
4. On mobile, the plugin folder lives inside the vault's `.obsidian/plugins/` directory;
   the same three files apply. BRAT users can add `258044aamm-Dev/Tablify` and pin tag
   `v2.0.0-beta.5`.

## Rollback

To return to 2.0.0-beta.4, download its `main.js`, `manifest.json`, and `styles.css`
assets and replace those files in the plugin folder. Nothing in this release rewrites
existing tables — a downgrade loses only the new pickers, the rendering changes and the
focusing fix; keep Tablify 2.x installed for any table that contains formula or link
fields.
