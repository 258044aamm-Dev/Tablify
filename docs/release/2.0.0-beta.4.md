# Tablify 2.0.0-beta.4 — Field editor and a cleaner header

- **Release date:** 2026-10-17
- **Tag:** `v2.0.0-beta.4`
- **Channel:** Pre-release
- **Minimum Obsidian version:** 1.14
- **File format:** unchanged (no migration; `formatVersion` rules are the same as beta.3)

## Highlights

- **A field is edited in the same window that creates one (COD-67).** Click a column header, or
  choose **Field details…** from its ⋮ menu (right-click opens the same menu), and **Edit Field**
  opens with the field's name and type. It is the **Add New Field** dialog in edit mode — one
  layout, not a second window. Only types that convert every existing value are offered, the same
  rule the old type picker applied; the current type is always selectable.
- **Fields can be renamed for the first time (COD-67).** Rename rewrites every `{Old name}` in the
  table's formulas and the old name in the saved view query (`Price:>10` becomes
  `"Unit Price":>10`), in **one undo step**. Names must be non-empty and unique within the table.
  Renaming and retyping together is also one step; if the type change would lose values, neither
  half is applied. Cell values and row revisions are untouched by a rename, and Airtable sync is
  unaffected because it maps fields by id.
- **Column headers show only the field name (COD-67).** The type badge — an icon plus the type
  label — is gone, and the freed width goes to the name. The type remains available to menus and
  automation through the header cell's `data-field-type` attribute. This is a deliberate
  divergence from the prototype design, which still draws the badge.
- **The header menu now says *Field details…* instead of *Change field type…*.** It opens the
  editor rather than the type-only picker; that picker had no other caller and is removed. Sorting,
  dragging, resizing, hiding and freezing a column work exactly as before, and a drag no longer
  risks being read as a click on the field.
- **Two editor fixes from the all-fields verification ride along:** a `date_time` cell now shows
  its stored time and no longer erases the value when opened and dismissed (COD-68), and
  double-clicking a cell opens its editor again after the selection repaint broke it (COD-66).

## Compatibility and known limitations

This release does not change the `.tablify` file format. Tables using formula or link fields are
still saved as format version 2 and cannot be opened by Tablify 1.0.2 or earlier; update every
device before using those fields. A table written by beta.3 opens unchanged in beta.4 and the
reverse is true as well.

Live Airtable and Obsidian runtime checks remain owner-run: the sync is tested against a fake
server. The visual-parity suite no longer scores the prototype's header type badge, because this
release removes it on purpose.

## Installing on a device

1. Download the three assets above from the release page.
2. Put them in `<vault>/.obsidian/plugins/tablify/`, replacing the existing files.
3. In Obsidian: **Settings → Community plugins**, then disable and re-enable **Tablify** (or
   reload the app) so the new `main.js` is loaded.
4. On mobile, the plugin folder lives inside the vault's `.obsidian/plugins/` directory; the same
   three files apply. BRAT users can add `258044aamm-Dev/Tablify` and pin tag `v2.0.0-beta.4`.

## Rollback

To return to 2.0.0-beta.3, download its `main.js`, `manifest.json`, and `styles.css` assets and
replace those files in the plugin folder. Nothing in this release rewrites existing tables, so a
downgrade loses only the new field editor; keep Tablify 2.x installed for any table that contains
formula or link fields.
