# P7-01 — Embed code block

- **Linear:** SAD-50
- **Phase:** P7 — Embeds and Airtable sync (v1.1) (see `spec/phases/P7.md`)
- **Scope:** v1.1
- **Read first:** `spec/glossary.md`, `spec/guidelines.md` §0 (rules) and §1 (assumptions), `spec/roadmap.md` §3 (decisions)
- **Source:** copied unchanged from `spec/guidelines.md` (section for P7-01)

- **Objective:** A note can show and edit a `.tablify` table.
- **Prerequisites:** P3-01, P1-03.
- **Actions:**
  1. Register a code block processor for the fence language `tablify`. Body is the file path.
  2. Render the grid in a limited size with a link to open the full view.
  3. Edits save to the source file through the same command path.
  4. Maintain one in-memory store per file. Two embeds and the full view share it.
  5. External file change: reload the store, keep the cursor position where possible.
- **Dependencies:** P3-01, P1-03.
- **Outputs:** `src/embed/*`, tests.
- **Verification:**
  - T-E: two embeds of the same file. Edit in one; the other updates after save.
  - T-E: external edit to the file (through another editor) reloads the view.
  - T-E: missing file shows an error block, not a crash.
- **Performance:** Embed of FX-S renders < 300 ms (proposed).
- **Acceptance:** All checks pass with evidence.
