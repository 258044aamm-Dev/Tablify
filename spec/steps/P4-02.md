# P4-02 — XLSX spike and library decision

- **Linear:** SAD-37
- **Phase:** P4 — Import and export (see `spec/phases/P4.md`)
- **Scope:** MVP
- **Read first:** `spec/glossary.md`, `spec/guidelines.md` §0 (rules) and §1 (assumptions), `spec/roadmap.md` §3 (decisions)
- **Source:** copied unchanged from `spec/guidelines.md` (section for P4-02)

- **Objective:** Choose an XLSX reader and writer that work on mobile and do not use Node APIs.
- **Prerequisites:** none.
- **Actions:**
  1. Build two candidate spike branches (read-excel-file and one browser-safe writer, plus one alternative) that load FX-XLSX.
  2. Measure bundle size delta for each.
  3. Check that the bundled output contains no `require("fs")` or other Node-only imports.
  4. Test on iOS and Android in a test build.
  5. Write `docs/decisions/xlsx.md` with the scores, measurements, and the chosen library.
- **Dependencies:** none.
- **Outputs:** Decision record, spike code (not shipped).
- **Verification:**
  - T-I: spike reads FX-XLSX and returns the same row count and values as a reference read (the generator's known values).
  - T-S: grep the bundle for Node-only imports; zero matches.
  - T-M-DEV: plugin loads and reads a file on iOS and Android.
- **Performance:** Read FX-XLSX (5,000 rows) timing recorded for each candidate. Target: under 3,000 ms desktop (proposed).
- **Acceptance:** Decision record complete with measured numbers. Chosen library passes all checks. Known fidelity limits written in the record (for example, formulas read as cached values only).
