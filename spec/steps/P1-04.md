# P1-04 — Validation engine

- **Linear:** SAD-22
- **Phase:** P1 — Data core (see `spec/phases/P1.md`)
- **Scope:** MVP
- **Read first:** `spec/glossary.md`, `spec/guidelines.md` §0 (rules) and §1 (assumptions), `spec/roadmap.md` §3 (decisions)
- **Source:** copied unchanged from `spec/guidelines.md` (section for P1-04)

- **Objective:** Rules are checked consistently, with no crash on bad rule config or pathological input.
- **Prerequisites:** P1-01.
- **Actions:**
  1. Rules: required, unique, min, max, regex.
  2. Unique: compare trimmed values, case-sensitive by default (document this as an assumption).
  3. Regex: compile once when the rule is set; reject an invalid pattern at config time.
  4. Limit regex input length to 10,000 characters and document that cap, to avoid catastrophic backtracking.
  5. Validation returns a list of violations with row ID, field ID, and rule name. It does not modify data.
- **Dependencies:** P1-01.
- **Outputs:** `src/model/validation.ts`, tests.
- **Verification:**
  - T-U: each rule with a positive and negative case.
  - T-U: invalid regex config rejected.
  - T-P: a known ReDoS-style pattern and input (for example `(a+)+$` with 30 `a`s then `b`) is either rejected at config time or returns in under 100 ms.
  - T-M: random tables validated incrementally vs. full recompute. Results must be identical.
- **Performance:** Full validation of FX-M < 50 ms (proposed).
- **Acceptance:** All rule tests pass. Regex safety test passes. Incremental and full results match.
