# P1-01 — Field type registry

- **Linear:** SAD-19
- **Phase:** P1 — Data core (see `spec/phases/P1.md`)
- **Scope:** MVP
- **Read first:** `spec/glossary.md`, `spec/guidelines.md` §0 (rules) and §1 (assumptions), `spec/roadmap.md` §3 (decisions)
- **Source:** copied unchanged from `spec/guidelines.md` (section for P1-01)

- **Objective:** Each of the 19 field types has one implementation for validate, parse, format, default, and read-only status.
- **Prerequisites:** P0-03 (spec defines the types).
- **Actions:**
  1. Define a `FieldType` interface: `validate(value)`, `parse(input: string)`, `format(value)`, `defaultValue()`, `readOnly: boolean`.
  2. Implement user types: text, long text, number, currency, percent, duration, rating, checkbox, date, date & time, URL, email, phone.
  3. Implement select types: single select, multi select (reference options by option ID).
  4. Implement attachment (vault-relative path string), auto number (read-only), created time and modified time (read-only, ISO 8601 UTC).
  5. Register all types in one registry. Unknown type names in a file produce an error, never a silent default.
- **Dependencies:** P0-03.
- **Outputs:** `src/model/fieldTypes/*`, registry, tests.
- **Verification:**
  - T-U: table-driven tests per type with valid, invalid, and empty values (at least 5 cases each).
  - T-M: for each type, `parse(format(v))` equals `v` for 1,000 random valid values from seeded generators.
  - Edge cases tested: currency rounding (store as integer minor units, state the unit in the spec), duration formats, leap-day dates, URLs with unicode, phone numbers with leading `+`.
  - Coverage of the registry module reported. Target: ≥ 95% line coverage (proposed). Report the actual value.
- **Performance:** Validating 10,000 values across all types < 50 ms desktop (proposed).
- **Acceptance:** All tests pass. Every registered type has a test. Unknown types rejected with a clear error.
