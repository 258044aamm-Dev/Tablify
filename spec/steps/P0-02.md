# P0-02 — Tooling

- **Linear:** SAD-16
- **Phase:** P0 — Foundation and format spec (see `spec/phases/P0.md`)
- **Scope:** MVP
- **Read first:** `spec/glossary.md`, `spec/guidelines.md` §0 (rules) and §1 (assumptions), `spec/roadmap.md` §3 (decisions)
- **Source:** copied unchanged from `spec/guidelines.md` (section for P0-02)

- **Objective:** Lint, unit test, and build run with one command each, and failures are visible.
- **Prerequisites:** P0-01.
- **Actions:**
  1. Configure ESLint with the Obsidian-recommended rules (use the official sample plugin's config as the reference).
  2. Configure Vitest with coverage output.
  3. Add npm scripts: `lint`, `test`, `test:coverage`, `build`, `check` (runs all).
  4. Decide and record the UI test approach for G-L1 (automated runner, or manual scripts with a template).
  5. Add a CI workflow (or a local script) that runs `check`.
- **Dependencies:** P0-01.
- **Outputs:** config files, `docs/testing/approach.md`, CI file.
- **Verification:**
  - Clean clone: `npm ci && npm run check` passes.
  - Negative test: add an intentional lint violation and a failing unit test on a branch. Both must fail the check. Revert and record.
- **Performance:** `npm run check` on a clean clone completes in under 5 minutes on the reference machine (proposed).
- **Acceptance:** Clean clone passes `check`. Negative test proves the check fails when it should. UI test approach documented.
