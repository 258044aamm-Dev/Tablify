# P1-02 — Row store

- **Linear:** SAD-20
- **Phase:** P1 — Data core (see `spec/phases/P1.md`)
- **Scope:** MVP
- **Read first:** `spec/glossary.md`, `spec/guidelines.md` §0 (rules) and §1 (assumptions), `spec/roadmap.md` §3 (decisions)
- **Source:** copied unchanged from `spec/guidelines.md` (section for P1-02)

- **Objective:** A correct in-memory table with stable IDs, timestamps, revisions, and auto numbers.
- **Prerequisites:** P1-01.
- **Actions:**
  1. Store rows in a map keyed by row ID, plus an ordered list for display order.
  2. Generate row IDs with at least 80 bits of randomness, prefixed `row_` (G-A6).
  3. Keep an auto-number counter in table metadata. Never decrement it or reuse numbers.
  4. On each change: increment `rev` by exactly 1 and set `updatedAt` to UTC now.
  5. Expose create, read, update, delete, and reorder operations. Each returns the changed row and never mutates input objects.
- **Dependencies:** P1-01.
- **Outputs:** `src/model/tableStore.ts`, tests.
- **Verification:**
  - T-U: each operation's contract, including input immutability.
  - T-U: 10,000 generated IDs are unique. Record the count and result.
  - T-M: random sequence of 10,000 operations applied to both the store and a simple array-based reference model. Results must match after every operation (check on a sample every 100 steps and at the end).
  - T-U: auto number not reused after delete.
- **Performance:** Create 1,000 rows < 100 ms. Single update < 1 ms (proposed).
- **Acceptance:** Model test matches for all operations. ID uniqueness holds. Auto number never reused.
