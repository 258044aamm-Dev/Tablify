# P1-05 — Undo and redo

- **Linear:** SAD-23
- **Phase:** P1 — Data core (see `spec/phases/P1.md`)
- **Scope:** MVP
- **Read first:** `spec/glossary.md`, `spec/guidelines.md` §0 (rules) and §1 (assumptions), `spec/roadmap.md` §3 (decisions)
- **Source:** copied unchanged from `spec/guidelines.md` (section for P1-05)

- **Objective:** Local edits can be undone and redone in order.
- **Prerequisites:** P1-02.
- **Actions:**
  1. Each command stores its `do` and `undo` data (not full table snapshots).
  2. Coalesce consecutive edits to the same cell within 1 second into one command (assumption, document it).
  3. Stack limit 100. When full, drop the oldest command.
  4. A new command after an undo clears the redo stack.
  5. Pull and push are not commands (R-D14). Provide a `clear()` used after sync.
- **Dependencies:** P1-02.
- **Outputs:** `src/model/commands.ts`, tests.
- **Verification:**
  - T-M: 1,000 seeded random sequences of commands. After undoing all, the state equals the initial snapshot. After redoing all, the state equals the state before undo.
  - T-U: redo cleared after a new command; limit of 100 enforced; coalescing rule tested with fake timers.
- **Performance:** Apply and undo one command on FX-M < 16 ms (proposed).
- **Acceptance:** 1,000 sequences pass. All unit cases pass.
