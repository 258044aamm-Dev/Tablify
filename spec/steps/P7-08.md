# P7-08 — Conflict detection

- **Linear:** SAD-57
- **Phase:** P7 — Embeds and Airtable sync (v1.1) (see `spec/phases/P7.md`)
- **Scope:** v1.1
- **Read first:** `spec/glossary.md`, `spec/guidelines.md` §0 (rules) and §1 (assumptions), `spec/roadmap.md` §3 (decisions)
- **Source:** copied unchanged from `spec/guidelines.md` (section for P7-08)

- **Objective:** Every combination of local and remote change has a defined outcome, and nothing is overwritten silently.
- **Prerequisites:** P7-06, P7-07.
- **Actions:**
  1. Decision table with these cases: no change; local only; remote only; both changed to different values; both changed to the same value; remote deleted; local deleted.
  2. Conflict dialog offers keep local, keep remote, keep both (keep both creates a new row).
  3. Store the decision in the row's sync block so the same conflict is not asked again without a new change.
- **Dependencies:** P7-06, P7-07.
- **Outputs:** `src/sync/conflicts.ts`, dialog, decision table in `docs/sync-rules.md`.
- **Verification:**
  - T-I: one scripted scenario per case in the decision table. Record the outcome. Each must match the table.
  - T-I: keep both creates exactly one new row with the remote values.
- **Performance:** N/A.
- **Acceptance:** All seven cases match the table. No silent overwrite in any case.
