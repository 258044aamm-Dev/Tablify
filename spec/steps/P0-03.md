# P0-03 — Format spec v1

- **Linear:** SAD-17
- **Phase:** P0 — Foundation and format spec (see `spec/phases/P0.md`)
- **Scope:** MVP
- **Read first:** `spec/glossary.md`, `spec/guidelines.md` §0 (rules) and §1 (assumptions), `spec/roadmap.md` §3 (decisions)
- **Source:** copied unchanged from `spec/guidelines.md` (section for P0-03)

- **Objective:** A written, machine-checkable definition of `.tablify` v1.
- **Prerequisites:** Decisions D2, R-D8, R-D9, R-D10 in `ROADMAP.md`.
- **Actions:**
  1. Write `FORMAT_SPEC.md`. Cover: file encoding (UTF-8), line endings (LF), key order, indentation (2 spaces), trailing newline, every key, types, required vs optional, `formatVersion` rule, unknown-key rule, reserved `sync` and `syncLink` keys, and the statement that `.tabula` is not read.
  2. Write `tablify.schema.json` (JSON Schema draft 2020-12).
  3. Create samples in `samples/v1/`: `empty.tablify`, `typical.tablify` (generated from FX-S), `edge.tablify` (unicode, escaped quotes, newline in long text, empty values, unknown key, `sync: null`), and invalid samples in `samples/invalid/` (wrong type, missing `formatVersion`, duplicate field ID, row referencing unknown field ID).
  4. Ask a second reviewer to check the spec against the roadmap §7 contract.
- **Dependencies:** none (can start in parallel with P0-01).
- **Outputs:** `FORMAT_SPEC.md`, schema, samples, review record.
- **Verification:**
  - T-U: a schema validator (Ajv or equivalent) accepts every file in `samples/v1/` and rejects every file in `samples/invalid/` for the expected reason.
  - Checklist: every field in roadmap §7 appears in the spec. Count and list the items, record the result.
  - Review: reviewer sign-off recorded with the spec commit hash.
- **Performance:** N/A.
- **Acceptance:** All valid samples pass; all invalid samples fail with the expected error; reviewer sign-off recorded; spec states that `.tabula` files are not read.
