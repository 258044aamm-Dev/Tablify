# P7-06 — Pull

- **Linear:** SAD-55
- **Phase:** P7 — Embeds and Airtable sync (v1.1) (see `spec/phases/P7.md`)
- **Scope:** v1.1
- **Read first:** `spec/glossary.md`, `spec/guidelines.md` §0 (rules) and §1 (assumptions), `spec/roadmap.md` §3 (decisions)
- **Source:** copied unchanged from `spec/guidelines.md` (section for P7-06)

- **Objective:** Pull writes Airtable values into the file, keeps local-only rows, and can be safely re-run.
- **Prerequisites:** P7-02, P7-04, P7-05, P1-02.
- **Actions:**
  1. Fetch all records. Map values. Match rows by `sync.airtableId`.
  2. Remote-new records: add rows. Remote-deleted records: mark the local row as remote-deleted (do not delete silently). Local-only rows: keep.
  3. Write once, after the full fetch succeeds.
  4. Record `syncedRev` and last sync time.
  5. Clear the undo stack after pull (R-D14).
- **Dependencies:** P7-02, P7-04, P7-05, P1-02.
- **Outputs:** `src/sync/pull.ts`, tests.
- **Verification:**
  - T-I: pull a 200-record test table; compare each value with the test base export. Zero mismatches.
  - T-I: pull twice in a row; the second pull changes nothing.
  - T-I: fail the network mid-pull (test hook). The file is unchanged.
- **Performance:** 2,500-record pull time recorded (information only).
- **Acceptance:** Comparisons pass. Failure test leaves file unchanged. Idempotence confirmed.
