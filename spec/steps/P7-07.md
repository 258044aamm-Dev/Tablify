# P7-07 — Push

- **Linear:** SAD-56
- **Phase:** P7 — Embeds and Airtable sync (v1.1) (see `spec/phases/P7.md`)
- **Scope:** v1.1
- **Read first:** `spec/glossary.md`, `spec/guidelines.md` §0 (rules) and §1 (assumptions), `spec/roadmap.md` §3 (decisions)
- **Source:** copied unchanged from `spec/guidelines.md` (section for P7-07)

- **Objective:** Push sends only changed rows and reports partial failures clearly.
- **Prerequisites:** P7-02, P7-04, P7-05.
- **Actions:**
  1. Compute changed rows since `syncedRev`.
  2. Batch creates and updates within API limits (per the documented batch size).
  3. Record each success into the row's `sync` block. Keep failed rows marked as changed.
  4. Report partial failure with row IDs and reasons.
- **Dependencies:** P7-02, P7-04, P7-05.
- **Outputs:** `src/sync/push.ts`, tests.
- **Verification:**
  - T-I: change 10 rows of 200; push sends exactly 10 (count in the mock and live logs).
  - T-I: after push, pull compares equal to local for all 200 rows.
  - T-I: simulated failure on row 5 of a batch: the other rows succeed, row 5 stays changed, the report lists it.
- **Performance:** Information only.
- **Acceptance:** All checks pass.
