# P6-06 — Release

- **Linear:** SAD-49
- **Phase:** P6 — Hardening and release (see `spec/phases/P6.md`)
- **Scope:** MVP
- **Read first:** `spec/glossary.md`, `spec/guidelines.md` §0 (rules) and §1 (assumptions), `spec/roadmap.md` §3 (decisions)
- **Source:** copied unchanged from `spec/guidelines.md` (section for P6-06)

- **Objective:** Tagged 1.0.0 release with assets that install correctly.
- **Prerequisites:** P6-01 to P6-05 accepted. D-O3 (license) decided.
- **Actions:**
  1. Confirm license file is present (D-O3).
  2. Build from the tagged commit in a clean environment.
  3. Create the GitHub release with `main.js`, `manifest.json`, `styles.css`.
  4. Compute SHA-256 hashes of the three files and record them in the release notes.
  5. Write a rollback plan: previous version, how users revert, known issues.
  6. If using a build attestation workflow, verify the attestation after release.
- **Dependencies:** P6-01 to P6-05, D-O3.
- **Outputs:** Release, hashes, rollback plan, gate note.
- **Verification:**
  - Re-build from the tag. Hashes match the release assets (or differences are explained by documented build settings).
  - Install the release assets in a clean vault on desktop and mobile. Run A1 and A9.
- **Performance:** N/A.
- **Acceptance:** Hashes verified. Clean install passes on both device types. Rollback plan written.
