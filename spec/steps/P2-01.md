# P2-01 — Query parser

- **Linear:** SAD-25
- **Phase:** P2 — Query and view state (see `spec/phases/P2.md`)
- **Scope:** MVP
- **Read first:** `spec/glossary.md`, `spec/guidelines.md` §0 (rules) and §1 (assumptions), `spec/roadmap.md` §3 (decisions)
- **Source:** copied unchanged from `spec/guidelines.md` (section for P2-01)

- **Objective:** Parse the grammar in `FEATURES.md` §2.6 into an AST, with clear errors.
- **Prerequisites:** none in code. The grammar is in `FEATURES.md`.
- **Actions:**
  1. Write the grammar in `docs/query-grammar.md`, including tokenization, quoting, and whitespace rules.
  2. Implement tokenizer and parser. Pure module, no Obsidian imports.
  3. Errors include position (character offset) and a message.
  4. Document ambiguous cases, for example `field:a,b` for text (contains any) vs. multi-select (is any of). Decide and record.
- **Dependencies:** none.
- **Outputs:** `src/query/parse.ts`, grammar doc, tests.
- **Verification:**
  - T-U: at least 30 cases covering each operator row in the table, quoted names, case-insensitive names, empty value, and error cases.
  - T-F: 10,000 seeded random strings. No uncaught exception; every error has a valid position.
  - T-U: print-then-parse round trip gives an equal AST.
- **Performance:** Parse a 1 KB query < 1 ms (proposed).
- **Acceptance:** All tests pass. Fuzz clean. Ambiguous cases documented.
