# P1-03 — Serializer and parser

- **Linear:** SAD-21
- **Phase:** P1 — Data core (see `spec/phases/P1.md`)
- **Scope:** MVP
- **Read first:** `spec/glossary.md`, `spec/guidelines.md` §0 (rules) and §1 (assumptions), `spec/roadmap.md` §3 (decisions)
- **Source:** copied unchanged from `spec/guidelines.md` (section for P1-03)

- **Objective:** `.tablify` files read and written with no data change on a round trip, and invalid files are never overwritten.
- **Prerequisites:** P0-03, P1-02.
- **Actions:**
  1. Serializer: keys in the order defined by the spec, 2-space indent, LF, trailing newline, deterministic output.
  2. Parser: validate against the schema from P0-03 and report the first error with line and column.
  3. Preserve unknown keys on read and write them back in place.
  4. Check `formatVersion` before anything else. Unknown major version → error, no write.
  5. Write path: serialize to a string first. Only write if serialization and validation succeed. Use atomic replace where the platform supports it; otherwise write a temp file and rename.
- **Dependencies:** P0-03, P1-02.
- **Outputs:** `src/format/serialize.ts`, `src/format/parse.ts`, tests.
- **Verification:**
  - T-U: each sample in `samples/v1/` round-trips byte-identical.
  - T-U: each invalid sample returns the expected error with a line and column.
  - T-F: 10,000 seeded random mutations of a valid file. Parser must return either a valid model or an error, never throw. Record the count.
  - T-I: for an invalid file, the write path is never called (mock the vault and assert zero writes).
- **Performance:** PERF-3 save FX-M < 300 ms p95. Parse FX-M < 200 ms p95 (proposed).
- **Acceptance:** Round trips identical. Fuzz: zero uncaught exceptions. Invalid files untouched in T-I.
