# P3-09 — Design tokens and light/dark themes

- **Linear:** SAD-65
- **Phase:** P3 — Grid UI (see `spec/phases/P3.md`)
- **Scope:** MVP
- **Read first:** `spec/glossary.md`, `spec/branding.md`, `spec/guidelines.md` §0 and §1
- **Source:** written for this spec from `spec/branding.md` (owner decisions §2–§3, palette §5). Not in the guideline file.

- **Objective:** One token source for all table UI colors, spacing, and type. Light and dark Anthropic-inspired themes. The table uses these themes whatever the Obsidian theme is (owner decision, `spec/branding.md` §3).
- **Prerequisites:** P0-01 (scaffold and build).
- **Actions:**
  1. Create `src/ui/theme/tokens.ts` with the palette in `spec/branding.md` §5 (token names and hex values).
  2. Define a light and a dark theme map from those tokens.
  3. Apply the active theme through a plugin-scoped CSS class on the table root. Do not change Obsidian's global theme.
  4. Remove hard-coded color values from grid components. They must read tokens only.
- **Dependencies:** P0-01. P3-01 (SAD-28) and P3-10 (SAD-66) depend on this step.
- **Outputs:** `src/ui/theme/tokens.ts`; light and dark theme maps; theme class applied to the table root; evidence in `docs/evidence/P3-09.md`.
- **Verification:**
  - T-U: every token resolves to a value in both themes.
  - T-U: an automated search finds no color literal outside `tokens.ts`.
  - T-M: the grid is checked in light and dark themes, with Obsidian set to light and to dark. Layout is identical in all four combinations.
- **Performance:** Theme switch completes in under 100 ms (proposed, see `spec/guidelines.md` §0.7).
- **Acceptance:**
  - Token values match `spec/branding.md` §5.
  - No hard-coded colors in grid components.
  - Both themes render with identical layout.
  - The palette is still marked unverified until open decision G-B1 is closed (see P3-11).

# Notes
- The palette comes from a third-party summary. It is not confirmed against an official Anthropic source. See G-B1 in `spec/README.md`.
